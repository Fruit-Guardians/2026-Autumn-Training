```
n2 = 40296040179237842522563611839365332355790144526713788839335091723318191501651

c2 = 11575886152485600830900787187004584077914908915249220105766342985699103364460
```

**我的思路**

先尝试 gcd，发现一个很大的素数。既然是同一段明文、两组参数，那就用这个公因子把两个 n 都拆开，各求各的私钥，各解一次，两份结果互相对照。调用原有脚本。

**关键代码**

```python
p = gmpy2.gcd(n1, n2)
q1 = n1 // p
q2 = n2 // p

d1 = gmpy2.invert(e, (p - 1) * (q1 - 1))
d2 = gmpy2.invert(e, (p - 1) * (q2 - 1))

m1 = pow(c1, d1, n1)
m2 = pow(c2, d2, n2)
```

**结果**

```
flag{shared_p_is_bad}
```

## 题 2 · 指数很小

**数据**

```
e = 3
n = 1199620376901776263963106977595954239530133089703469049812085042029421638978013328176314741714178306066062...
c = 4233654443523697666269796623055819933675806538263728161674850112991867338039144179004530864851829714783703...
```

**我的思路**

很小的 e，低加密？如果明文足够短，m³ 可能还没超过 n，那密文就是明文的立方、根本没取模。先用 `c + k·n` 从 k=0 开始试着开立方。

**关键代码**

```python
def solve_low_exponent(n, e, c):
    k = 0
    while True:
        val = c + k * n
        m, exact = gmpy2.iroot(val, e)
        if exact:
            print(f"成了，k={k}")
            return long_to_bytes(int(m))
        k += 1
        if k > 100000:
            print("貌似大了，已中止")
            return None
```

**结果**

```
成了，k=0
flag{e_3_no_wrap}
```

k = 0 就开出来了，说明确实没有取模。

## 题 3 · 同一模数

**数据**

```
n  = 54522401341265580347021643086094850191694798543084060637143902826920061803427
e1 = 17
e2 = 65537
c1 = 15084858071776720559389984430215213718095943425122850465718095248262164672068
c2 = 49133819297709175326448270257699330759371579017972955468176938777775482246928
```

**我的思路**

共模可出。两个 e 互素，用扩展欧几里得求出 x、y 使 `e1·x + e2·y = 1`，再算 `c1^x · c2^y mod n`。

**关键代码**

```python
g, x, y = gmpy2.gcdext(e1, e2)
if g != 1:
    print("非互素，滚木")

if x < 0:
    x = -x
    c1 = gmpy2.invert(c1, n)
if y < 0:
    y = -y
    c2 = gmpy2.invert(c2, n)

m = (pow(c1, x, n) * pow(c2, y, n)) % n
```

**结果**

```
flag{same_n_two_e}
```

## 题 4 · e 特别大

**数据**

```
n = 68253396267261385157333304769929444204122691416598002196980402679825499936667
e = 24621756375635850963076291158190139830864284570146973847894277524271613651829
c = 51035793088174232414564316200409757532286774273329731843228124648021012402295
```

**我的思路**

放进去，位数异常大——e 和 n 差不多长。是维纳吗？维纳的前提是 d 很小，d 小的话 e/n 会非常接近 k/d，用连分数展开取收敛子就能试出来。

**关键代码**

```python
cf = continued_fraction(Rational(e, n))
for frac in continued_fraction_convergents(cf):
    k, d = int(frac.p), int(frac.q)
    if k == 0 or (e * d - 1) % k:
        continue
    phi = (e * d - 1) // k
    b = n - phi + 1
    delta = b * b - 4 * n
    if delta < 0:
        continue
    s, exact = gmpy2.iroot(delta, 2)
    if exact:
        p, q = (b + s) // 2, (b - s) // 2
        if p * q == n:
            return d, p, q
```

**结果**

```
flag{small_d_hurts}
```

## 题 5 · 多给了一个数

**数据**

```
n   = 63703629026833621135900933110090771404050883668018199030553117375964718776381
e   = 65537
c   = 33179359739784778217814201371725362215677108095435317911829220961010574821294
phi = 63703629026833621135900933110090771403531853786051683853625684934049077996764
```

**我的思路**

欧拉白给，韦达启动！phi 给了等于把 p+q 给了：`p + q = n - phi + 1`，再解 `x² - (p+q)x + n = 0`。

**关键代码**

```python
b = n - phi + 1
delta = b * b - 4 * n
s, exact = gmpy2.iroot(delta, 2)

if exact:
    p = (b + s) // 2
    q = (b - s) // 2
    print(f"[+] 成功分解 N:\np = {p}\nq = {q}")

    d = gmpy2.invert(e, phi)
    m = pow(c, d, n)
    print(long_to_bytes(m).decode('utf-8', errors='ignore'))
```

**结果**

```

p = 319883604764312474259843858016644891319
q = 19914627720220270266758858389899588299
flag{extra_info_helps}
```

# 二、DSH 点评

## 总评

五题全对，从第一题到交卷共 25 分钟。比"做对"更值得说的是：**每一题你都是先看数、再判断、最后才动手**。这在 RSA 里是最值钱的能力——RSA 的题面往往只有几个数字，攻击类型是靠数字的"长相"判断出来的，不是靠背模板。

## 逐题

**题 1（共享素数）**

做得好的：拿到 p 之后两个 n 都解了一遍，互相印证。这个习惯能防止"算错了还以为对"。

可以改进：其实解一组就够，第二组留着做验证即可，不必重复建两套 RSA 参数。

**题 2（低加密指数）**

做得最好的就是那句「成了，k=0」。很多人会机械地从 k=0 开始循环，但没意识到 k=0 意味着密文本身就是明文的三次方、根本没取模。先判断 `m^e < n` 能直接省掉整个循环。

可以改进：判断可以更显式，例如先算 `gmpy2.iroot(c, e)`，`exact` 为真就直接结束；或者比较位数。

**题 3（共模攻击）**

一眼识别「共模可出」，说明这类题的形态已经记牢了。

可以改进：负数指数的处理写对了，但要记住这是**必须**的——`x`、`y` 里必有一个是负的（因为 e1、e2 互素且都大于 1），漏了这步会直接抛异常。

**题 4（维纳攻击）**

「位数异常大 → 是维纳吗？」这个判断路径非常正确。维纳的识别特征就是 e 与 n 位数相当。

可以改进：可以量化——先看 `n.bit_length() // 4`（即 d 的理论上限位数），再看 e 的位数；e 和 n 一样长，基本就是维纳，不必犹豫。

**题 5（已知 φ）**

「欧拉白给，韦达启动！」一句话点到本质：`φ(n) = n - (p+q) + 1`，所以给了 φ 就等于给了 p+q。

可以改进：**开平方要用 `math.isqrt` 或 `gmpy2.iroot`，绝不能用 `x ** 0.5`**。256 位以上的数用浮点开方会丢精度，算出来的判别式不是完全平方数，p、q 就解不出来，而且报错很隐蔽（只会走到 else 分支）。

## 三条建议

**1. 大位数场景要换工具。** 这次用的是 128 / 256 位素数，真实赛题是 512 / 1024 位。`sympy.nthroot_mod` 在大位数上会卡住（内部要对 p-1 做分解），到时候必须用 Sage 的 `Mod(c, p).nth_root(e, all=True)`。

**2. 把套路沉淀成工具库。** 五道题五种套路，建议合并成一个 `rsa_toolkit.py`，一个套路一个函数，以后遇到直接调，别每次重写。

**3. 按清单往下走。** 这一轮打通了：共享素数、低加密指数、共模、维纳、已知 φ、e 与 φ 不互素。清单上还剩：dp 泄露、Boneh-Durfee、Franklin-Reiter、Coppersmith。后三个都要用格（LLL），建议先把 dp 泄露练熟。
