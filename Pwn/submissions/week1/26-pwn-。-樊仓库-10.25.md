## 10 月 23 日之前的自学总结

### 一、C 语言

之前读《C 程序设计》，看得快，忘得也快。所以最近回头重学数组与指针。

#### 1. 数组与指针：几个新的认识

**认识一：`arr` 不是指针，它的类型是 `int[3]`。**

```
sizeof(arr)      = 12
sizeof(arr[0])   = 4
sizeof(arr + 0)  = 8     // 加了 +0 就退化成指针
```

`sizeof` 和 `&` 是仅有的两个"不吃退化"的地方。`sizeof(arr)` 能算出 12，说明在编译器眼里它是一块 12 字节的内存，而不是一个地址。

我以前把"数组名可以当指针用"直接记成了"数组名就是指针"，这两句话差得很远。

**认识二：`&arr` 和 `arr` 值一样，类型不一样。**

```
arr        // int *        → arr + 1 走 4 字节，一个元素
&arr       // int (*)[3]   → &arr + 1 走 12 字节，整个数组
&arr[0]    // int *
```

三个地址打印出来是同一串数字，但 `+1` 之后就分家了：一个走元素，一个走整个数组。所以比起"等不等"，更该问的是"那 `+1` 之后呢"。

**认识三：二维数组在内存里是一维连续的。**

`m` 是按行连着存的：`m + 1` 走一整行，`m[0] + 1` 走一个元素。

```
sizeof(m)  = 24      sizeof(m[0]) = 12
m + 1      → +12     m[0] + 1     → +4
&m[1][0] - &m[0][0] = 3
```

所以 `int (*p)[3]` 里的那个 `3` 不能丢——它决定了 `p + 1` 该走多远。这也顺便解释了为什么二维数组传参必须写 `int m[][3]`。

**认识四：函数参数里的那个 `3`，会被直接丢掉。**

```c
static void show(int a[3]) {
    printf("%zu\n", sizeof(a));      // 打印 8，不是 12
}
```

编译器自己会给一条 warning：

```
warning: 'sizeof' on array function parameter 'a' will return size of 'int *'
```

原因有两个：C 的参数**全部按值传递**，12 字节的数组没法整个复制进栈，只能传首地址；而形参里的 `[3]` 会被直接丢弃，`int a[3]`、`int a[]`、`int *a` 对编译器完全等价，那个 `3` 只是写给人看的注释。

这条顺带解释了我一直觉得奇怪的事：`gets`、`strcpy` 为什么不知道边界。好像是 `char *gets(char *s)` 这个签名里**根本没有第二个参数能装长度**。

**认识五：`a[i]` 就是 `*(a + i)`，而 `[]` 不做任何检查。**

```c
arr[2]  ==  *(arr + 2)  ==  2[arr]      // 三个都是 30，因为加法可交换

int *p = &arr[1];
p[-1]                                   // 负数下标照样过，编译器一声不响
```

越界这一次只是运气好，读的是紧挨着的内存。等 `arr` 换成栈上的 `char buf[64]`、越界写到第 72 个字节，写的就是返回地址——栈溢出就是从这儿进去的。

**总之吧：数组没有"值"，只有"地址 + 长度"这个契约。语言只负责给地址，长度要人自己记。**

这句话后来在汇编里对上了：`arr` 在代码里就是一个 `lea`，`arr[i]` 就是 `[base + index*4]`。**数组在汇编里根本不存在，只剩地址和偏移。**

#### 2. 指针：从头补起

指针我自认为学得不好，就从头过一遍，目前还没看完。

- **地址与解引用**：`&` 和 `*` 到底在做什么。
- **指针运算**：加减的步长、指针之间的比较、二级指针。
- **数组退化**：正好和上面接上了——`a[i]` 等价于 `*(a + i)`，所以越界不会报错。
- 另外在琢磨 `int (*p)[3]` 这种"指向数组的指针"是怎么解引用二维数组的。

学之前我一直以为 `p` 里存的是 5 这种值。用一个最土的比方纠正过来：**`p` 是一张写着门牌号的纸条，`*p` 是按号码进屋取东西。**

```
&a  = 000000000062FE44
p   = 000000000062FE44        // 一模一样
```

三件事同时被证明：`p` 里从头到尾只有地址，没变过；`*p = 8` 改的是房间里的东西，纸条没动；`p = NULL` 之后 `a` 还是 8，两块内存互不影响。

还有个当时看不懂的数字差：

```
0x62FE4C − 0x62FE40 = 0xC = 12
```

拆开是 `p`（8 字节指针）+ 4 字节对齐填充 + `a`（4 字节 int）。8 字节的变量必须落在 8 的倍数地址上，`int` 只要求 4 的倍数，中间就空了一块。**这 4 个字节的目的**——以后算结构体布局、算 payload 长度，天天要跟它打交道。

### 三、数据结构：稍微了解了一下吧

例如什么是栈什么是堆和队列和链表吧，数的话有点难没有搞太懂，这里先把弄明白的那部分写下来。

先说一个我之前完全没有意识到的区分：**逻辑结构**和**存储结构**是两件事。逻辑结构讲"元素之间是什么关系"（线性、树、图），存储结构讲"这些关系在内存里怎么摆"（连续、分散）。同一个逻辑结构可以有不同的存储方式，这个分层一想通，后面的东西就不那么虚了。

- **栈**：后进先出，只在顶端进出。像一摞盘子，抽只能抽最上面那个。
- **队列**：先进先出，一头进、一头出。
- **链表**：每个结点自己带一个"下一个在哪"的指针。不需要连续内存，但也因此不能 `a[i]` 直接跳到第 i 个，只能从 `head` 顺着 `p = p->next` 一路走过去。
- **数组**：反过来，随机访问是 O(1)，但插入删除要挪一大片。

还有一个词把我绕进去过：**「堆」有两个意思**。数据结构里的堆是二叉树那一类（优先队列），而内存里的 heap 是 `malloc` 的那块自由内存。它们只是撞了名字，不是一回事。

### 两道题

**题一：这几个 sizeof 和 strlen 是多少？**

```c
char  s[] = "hello";
char  d[10] = "hello";
char  e[] = {'h','e','l','l','o'};
char *p = "hello";

printf("%zu %zu\n", sizeof(s), strlen(s));   // 6 5
printf("%zu %zu\n", sizeof(d), strlen(d));   // 10 5
printf("%zu %zu\n", sizeof(e), strlen(e));   // 5 10（我机器上是 10）
printf("%zu %zu\n", sizeof(p), strlen(p));   // 8 5
printf("%zu\n",    sizeof(s + 0));           // 8
```

**sizeof 问类型多大，编译期就定死了吧；strlen 问 `'\0'` 前面有几个字节，运行期真去数。**

所以 `d` 是 10 不是 6（sizeof 只看声明），`p` 是 8（指针就 8 字节，跟指向啥无关），`s + 0` 是 8（加个 0 就退化了）。

`e` 那行：它没有 `'\0'`，`strlen` 会一直往后数。我机器上读到 10，说明越过数组又多读了 5 个字节才碰到 0。这个数换台机器就可能变了。

**题二：**

```c
struct S1 { char a; int  b; char  c; };   // 12
struct S2 { char a; char c; int   b; };   // 8
struct S3 { char a; };                    // 1
struct S4 { char a; short b; char c; };   // 6

offsetof(struct S1, b)   // 4
offsetof(struct S1, c)   // 8
```

**每个成员落在自己大小的整数倍偏移上，总大小补齐到最大成员的整数倍。**

S1 走一遍就懂了：a 在 0，1~3 空着，b 从 4 开始，c 在 8，最后补齐到 12。S2 只是把 c 提前一位，就省了 4 字节——成员顺序也是成本。

S4 最容易算错：最大成员是 `short`（2 字节），所以 5 补齐到 6，不是 8。

位域那两行：

```c
struct F1 { unsigned      a:3; unsigned      b:4; unsigned      c:1; };  // 4
struct F2 { unsigned char a:3; unsigned char b:4; unsigned char c:1; };  // 1
```

位数加起来都是 8，但 F1 占 4 字节——**单位大小看类型，不看位数**，没用满也不给。

赋值 `f.a = 8` 会变成 0，`f.b = 20` 变成 4。GCC 会甩个 warning，但程序照跑。所以位域不是省空间的开关，是"我用不满这几位，多的直接扔"。

## 10 月 25 日

今天主要是把**读懂汇编、吃透内存与栈帧**。它其实就两句话——能在 GDB 里看懂任意函数的反汇编和栈帧；能说清一次函数调用在内存里到底发生了什么。



```c
int add(int a, int b) { return a + b; }
int main(void) { return add(1, 2); }
```

```bash
gcc -O0 -g t.c -o t && gdb ./t
(gdb) b main
(gdb) run
(gdb) disassemble /m main     # 汇编和源码对着看
(gdb) si                      # 一条一条走
(gdb) info registers rsp rbp rip
(gdb) x/4gx $rsp              # 看栈顶那几十个字节
```

走一遍之后 `call` 终于不抽象了：跳之前 `rsp` 先减 8，把**下一条指令的地址**塞进去；进函数第一件事 `push rbp` 存旧的栈底，`mov rbp, rsp` 立新的栈底，再 `sub` 一块空间给局部变量（`add` 的两个参数就是从 `edi`、`esi` 搬进 `-4(%rbp)`、`-8(%rbp)` 的）。

`ret` 干的是反过来的事：把刚才压的那个地址弹回 `rip`。

所以前几天写的"栈溢出能改 PC"，机制就一行——**`ret` 弹什么，程序就跳什么。谁能写到那个位置，谁就能决定它跳哪。**

卡点：`x/4gx $rsp` 出来四行十六进制，我还分不清哪个是返回地址、哪个是 saved rbp。
