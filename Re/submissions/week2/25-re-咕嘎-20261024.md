### 一、PE文件
#### 1.PE文件包括
- .exe
- .dll
- .sys
#### 2.DOS Header
##### 作用：
- 标识文件类型：第一个字段 `e_magic` 固定是 `0x5A4D`。系统也凭借这个来判断文件是否为合法的可执行文件
- 定位真正的PE开头：最后一个字段 ` e_lfanew`  存了一个偏移量，系统靠它直接跳到文件里真正的 PE 头 `IMAGE_NT_HEADERS` 的位置
#### 3.DOS Stub
##### 作用：
用于兼容旧环境，常见提示：
```c
This program cannot be run in DOS mode.
```

#### 4.NT Header
PE 文件真正的核心控制中枢，Windows 加载程序通过 DOS 头里的  `e_lfanew ` 字段跳到它这里，从这里才开始真正解析这个程序。它由以下部分构成：
- PE签名
- 文件头：固定20字节，描述文件的基础属性
- 可选头：必须存在，决定程序在内存里怎么加载、怎么跑
- 程序入口点
- 镜像基址
- 节表相关信息

### 三、UPX
#### 1.作用：对程序进行加壳压缩包装。加壳的目的如下：
- 压缩体积

- 增加静态分析难度

- 运行时再解压或解密原始程序

#### 2.如何判断程序是否加壳
- 区段名称异常：用 PE 查看工具看区段名，如果出现  UPX0 、 UPX1 、 .aspack 、 .adata  这类非常规名称，基本就是加壳了。
- 入口点异常：正常编译的 VC++ 程序入口通常是  push ebp / mov ebp, esp  这种固定套路；加壳程序入口点往往指向非常规地址，且开头是一段"保存寄存器、设置栈帧、跳转解压代码"的模式。
- 文件体积异常：加壳后文件体积可能异常偏小，或文件大小与内存加载后的大小差异显著。
#### 3.如何使用UPX
##### （1）安装
从GitHUb上下载Windows版本的压缩包。解压缩后，将  upx.exe  文件地址加入 path 环境变量中。
##### （2）使用
在Windows终端中通过命令使用，以下是常用命令：
| 功能 | 命令 |
| :---: | :---: |
| 压缩文件（覆盖原文件）  |  upx example.exe  |
| 压缩并指定输出文件名    |  upx -o packed.exe example.exe  |
| 最高压缩率    |  upx -9 example.exe  或  upx --best example.exe  |
| 解压/脱壳    |   upx -d packed.exe  |
| 解压并指定输出文件名    |   upx -d packed.exe -o original.exe  |
| 测试文件是否为 UPX 壳   |   upx -t packed.exe  |
| 查看压缩信息  |   upx -l packed.exe  或  upx --info packed.exe  |
| 显示版本号  |  upx -V |

注意：压缩级别  `-1`  到  `-9` ：数字越大压缩率越高但耗时越长，默认  `-7` ，推荐用  `-9`  或  `--best`

### 四、Patch入门
#### 1.作用
Patch 就是修改程序的指令或数据，让程序行为发生变化。在 CTF 逆向入门里，常见 Patch 是：
- 把失败跳转改成成功跳转
- 把某些指令改成  `nop` ：`nop` 是空操作，如果某些指令只是干扰分析，可以尝试 NOP 掉。但要注意不能破坏程序必要逻辑
- 把条件跳转改成无条件跳转
- 修改比较值
#### 2.IDA中Patch的基本思路
- 找到要修改的指令
- 进入 Patch program 相关功能
- 修改汇编或字节
- 应用修改
- 导出修改后的程序
- 运行验证
### 五、花指令
#### 1.作用
花指令是为了干扰反汇编、反编译或人工阅读而插入的无效、冗余或误导性指令。它的目的不是实现业务逻辑，而是让你看不懂、让工具分析错、让伪代码变乱。
#### 2.常见类型
（1）无意义指令
```text
nop
push eax
pop eax
```

执行前后对程序状态几乎没有影响。
（2）跳过垃圾代码
```
jmp real_code
db 0E8h
db 0FFh
db 0FFh
real_code:
```

中间的字节可能不会被执行，但会干扰反汇编
（3）恒真或恒假的判断
```
xor eax, eax
test eax, eax
jz real_code
```

这里 `eax` 一定是 0，所以 `jz` 一定会跳
#### 3.如何应对花指令
- 判断这段代码是否真的会执行
- 看跳转最终到哪里
- 必要时 NOP 掉明显干扰指令，再让 IDA 重新分析
##### 4.实践题目
###### （1）第一题
步骤：
  1. 把文件拖给IDA进行反汇编 ，发现有 ` JUMPOUT  `报错，双击位置跳转
  2.  通过分析可知两种条件跳转都跳转到同一个位置，而且还是地址+1，是个典型的花指令，只需把跳转 `nop` 掉就行
  3.  把光标置于跳转目的地址处，点击 *Edit*  ，再点击 *Patch program* ，随后进入 *Change byte* 将 `E8` 更为 `90`
  4.  然后把标黄的地址都按 *C* 键进行修复，最后在 `main` 函数那里按 *P* 键进行重新构建函数
  5.  最后再按 *Tab* 键进行反汇编，得到flag
答案：NSSCTF{Jump_b9_jump!}
###### （2）第二题
步骤：
1. 把文件拖给IDA进行反汇编，发现 `main` 函数，双击跳转
2. 通过分析可知，有反复跳转的死命令，所以需要 `nop` 掉，即把 `EB` 改为 `90` 。但是由于目标太多，所以决定用脚本程序执行，以下是代码：
```c
static main() {
    auto start = 0x1144;
    auto end = 0x3100;
    auto i;

    for (i = start; i < end; i++) {
        if (Byte(i) == 0xEB && Byte(i + 1) == 0xFF && Byte(i + 2) == 0xC0) {
            PatchByte(i, 0x90);
        }
    }
}
```

3. 运行后，再次查看伪代码，可以看见右边灰色字里边藏有flag
答案：NSSCTF{u\_are2wordy}
###### （3）第三题
步骤：：
1. 把文件拖给IDA，直接展示了错误位置
2. 分析可知，与第一题类似，所以直接把 `E9` 改为 `90` ，然后进行反汇编
