# 三\.深入了解IDA操作步骤及其目的

### 一。IDA的大致操作过程：

打开 IDA → 选入口（新建 / 拖入 / 打开最近）→ 挑文件 → 弹出的加载框里确认"加载器 \+ 处理器" → IDA 开始分析，把二进制翻译成汇编给用户\-\-\>按下F5生成伪代码（提高了可读性）

·和实操对应 ，拖 test\_debug\.exe（windows程序） 进去时： 1\. 加载框里的"加载器"下拉如果同时列出 PE 和 MS\-DOS EXE 2\. 选 PE 3\. 处理器保持默认（x86/x64） 4\. 确定，等它分析

·加载器：

1、先搞懂"加载器"是干嘛的

IDA 打开一个文件，得先搞清楚"这是什么格式"，才知道怎么读。 加载器就是 IDA 用来识别格式的那套识别器 。 它按顺序挨个试：试 PE 加载器，试完不行再试别的。哪个能认出来，就用哪个。 

2、PE 是什么 PE = Portable Executable（可移植可执行文件格式） ，是 Windows 下可执行文件的 标准格式 。  \.exe、\.dll 文件，都是 PE 格式 。它内部有固定的结构：头部（header）、节区（section，如 \.text 存代码、\.data 存数据）、导入表、导出表等  。编译出的 test\_debug\.exe 就是 PE 格式，所以选 PE 加载器是对的。 

3、MS\-DOS EXE 是什么

MS\-DOS EXE 是 更老的一套格式 ——DOS 时代的可执行文件（\.exe），出现在 Windows 之前。 那为什么两个选项会同时出现？关键在这里： PE 格式为了兼容，保留了 DOS 时代的"外壳"。 一个现代 \.exe 文件，最开头其实还是一段"这是 DOS 程序"的旧头部（叫 DOS Header / MZ Header）。所以 IDA 去试加载器时，MS\-DOS EXE 加载器一看开头，觉得"这也像 DOS 程序"，就也报了名。 于是列表里就 同时出现两个候选 。

4、所以为什么选 PE 不选 MS\-DOS EXE 

如果选 MS\-DOS EXE ：IDA 只会把它当老式 DOS 程序解析，看不到现代 PE 的节区、导入表，分析等于跑偏 

选 PE ：IDA 才会正确解析出代码段、数据段、函数、导入的 API，才能正常看 main、看伪代码  一句话 ：两个都能"认出来"，但只有 PE 是"真的对"。MS\-DOS EXE 只是个兼容性的假象。 

5、什么时候才真的是 MS\-DOS EXE

只有当分析的 确实是一个纯 DOS 老程序 （比如 90 年代的 \.exe），选 MS\-DOS EXE 才对。现在遇到的 \.exe，几乎都是现代 PE，一律选 PE。

6\.另外，windows和linux可选择加载器区别

Windows 的 \.exe → 列表里看到 PE / MS\-DOS EXE → 选 PE 

Linux 的这个文件 → 列表里看到 ELF / 二进制 → 选 ELF

# 四，汇编语言的了解和反汇编的详解

### 一。汇编部分

汇编语言就是用助记符（比如MOV、ADD）来表示机器指令的低级编程语言。它比直接写二进制机器码要容易理解，但比高级语言更接近硬件。

1\.CPU和汇编的关系，CPU存储值方式

CPU 是硬件执行者，汇编是指令，寄存器是它的临时存储。汇编的作用就是操作CPU进行计算，CPU在计算的时候需要存储计算的值，这些值的存储位置就是CPU的寄存器，复杂的计算还需要内存辅助数据的存储

·存取速度层级

寄存器 \> 1级缓存 \> 2级缓存 \> 3级缓存 \> 内存 \> 硬盘。理解了这条，才明白为什么编译器拼命把变量往寄存器里塞。

### 二。反汇编部分

反汇编是将机器码转换为汇编代码的过程。

静态反汇编是在不运行程序的情况下分析程序结构，通过分析二进制文件来理解程序逻辑。

动态反汇编是在程序运行时分析其行为，可以获取程序的真实执行信息。
