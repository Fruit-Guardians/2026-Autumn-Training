# RE wk2 笔记——鳕鱼堡


### Patch

常见做法是改比较值、改跳转，或者把干扰字节改成 `nop`。

改跳转前先看哪条指令设置了标志位，再看跳转目标。`strcmp` 相等时返回 0。后面接 `test eax, eax`，`jz` 就会跳。

### 花指令

花指令就是用垃圾字节或跳转干扰分析。看到伪代码乱，先回到汇编，看程序实际跳到哪里。

```asm
xor eax, eax
test eax, eax
jz real_code
db 0E8h
real_code:
```

这里 `eax` 被清零，所以 `jz` 一定会跳。`E8` 不会执行，但 IDA 可能把它当成 `call`，导致后面的指令错位。相邻的 `jz` 和 `jnz` 若指向同一位置，也会形成必然跳转。

### Python 数据处理准备

逆向题里的数据可能是字符、整数、十六进制文本或 bytes。

```python
print(ord("A"))  # 65
print(chr(65))   # A

raw = bytes.fromhex("666c6167")
print(raw)        # b'flag'
print(raw.hex())  # 666c6167
```

`bytes.fromhex()` 把十六进制文本转成 bytes。`hex()` 可以把 bytes 转回十六进制文本。

### 位宽、大小端与数据分割

1 字节是 8 位。读取多字节整数时，先确认大小端。

```python
raw = bytes.fromhex("78563412")
print(hex(int.from_bytes(raw, "little")))  # 0x12345678
print(hex(int.from_bytes(raw, "big")))     # 0x78563412
```

按 4 字节分组时，每组分别转换。最后一组不满 4 字节，先看程序怎么填充。

### 基础可逆运算

同一个 key 异或两次，就能还原。字节加减要注意回绕，Python 里可以用 `& 0xff`。

```python
encoded = ((0x66 ^ 0x12) + 7) & 0xff
original = ((encoded - 7) & 0xff) ^ 0x12
assert original == 0x66
```

程序先 XOR、再加法，还原时就先减法、再 XOR。按位与和普通移位可能丢失信息，不能直接倒过来算。

### Base64

标准 Base64 把 3 字节编码成 4 个字符。常见字符是大小写字母、数字、`+`、`/`。末尾可能有 `=` 或 `==`。

遇到换表，先找程序实际使用的字符表。

###  HNCTF 2022 e@sy_flower

`re1.exe` 是 32 位 Windows 控制台程序。Detect It Easy 3.21 显示 MSVC 19.16，未识别出壳。

![ef28757e1c98c37a057b9833ecb705bc](https://imgdb.io/i/0U93eEk.png)

IDA 9.5 中分析到 `0x4010D4` 时，`E9` 被解释成指向 `9A085664` 的异常跳转，后续反汇编随之错位。

![IDA 原版把垃圾字节误识别为远跳转](https://imgdb.io/i/-EeEofk.png)

![修复分析副本后，Hex-Rays 显示交换、XOR 与 strcmp](https://imgdb.io/i/VE2PN_c.png)

`0x4010D0` 的 `jz` 和 `0x4010D2` 的 `jnz` 都跳到 `0x4010D5`。无论标志位取何值，`0x4010D4` 的 `E9` 都不会执行；Cutter 2.5 显示真实指令流从 `0x4010D5` 的 `mov eax, [var_3ch]` 继续。在分析副本中把文件偏移 `0x4D4`（VA `0x4010D4`）的 `E9` 改为 `90`，让反汇编器重新对齐。重新反编译后，主逻辑恢复为“相邻字节交换 → 每字节 XOR `0x30` → 与 `c~scvdzKCEoDEZ[^roDICUMC` 比较”。
