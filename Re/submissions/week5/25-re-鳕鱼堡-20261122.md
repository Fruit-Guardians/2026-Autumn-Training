## PE 文件结构

### 文件头和节表

文件开头是 `MZ`，在文件偏移 `0x3C` 处读取 4 个字节得到 `e_lfanew = 0x80`。跳到 `0x80` 可以看到 `50 45 00 00`，也就是 PE 签名。

| 字段 | 读数 |
| --- | --- |
| Machine | `0x8664`，x64 |
| Optional Header Magic | `0x20B`，PE32+ |
| NumberOfSections | `17` |
| AddressOfEntryPoint | `0x105F` |
| 首选 ImageBase | `0x140000000` |
| 节对齐 / 文件对齐 | `0x1000` / `0x200` |

用 Python 读取节表。校验代码在 `.text`，key 和目标数组在只读的 `.rdata`，可写的全局数据在 `.data` 或 `.bss`。与本次分析直接相关的节如下。

| 节名 | RVA | VirtualSize | 文件偏移 | SizeOfRawData |
| --- | ---: | ---: | ---: | ---: |
| `.text` | `0x1000` | `0x26B0` | `0x600` | `0x2800` |
| `.data` | `0x4000` | `0xC0` | `0x2E00` | `0x200` |
| `.rdata` | `0x5000` | `0x788` | `0x3000` | `0x800` |
| `.bss` | `0x9000` | `0x1A0` | `0` | `0` |
| `.idata` | `0xA000` | `0x9A4` | `0x4200` | `0xA00` |
| `.reloc` | `0xC000` | `0x60` | `0x4E00` | `0x200` |

### 地址换算

IDA 中目标数组的地址是 `0x140005060`。先减去首选基址得到 RVA，再用 `.rdata` 的起点换算到文件偏移。

```text
RVA = 0x140005060 - 0x140000000 = 0x5060
FOA = 0x5060 - 0x5000 + 0x3000  = 0x3060
```

从文件偏移 `0x3060` 读出的 10 字节是 `7b e3 2f 91 ac 8d 9c 1d d9 c8`。x64dbg 中模块实际加载在 `0x7FF661160000`，所以这次运行的目标地址是 `0x7FF661165060`。调试时用模块基址加 RVA 定位。像 `.bss` 这样没有原始文件数据的节，不能用节内偏移换算出对应字节。

### 定位校验

在字符串窗口找到 `XueYuBao_result: XueYuBao_pass`，查看交叉引用，回到 `main` 的 `0x140001986`。向上看，`0x14000197D` 调用 `XueYuBao_check`。PE 入口和 `main` 的 RVA 分别是 `0x105F` 和 `0x1876`。

`XueYuBao_check` 先用 `strlen` 取输入长度，接着用 `cmp rax, 0Ah` 判断是否正好 10 字节。长度满足后调用 `XueYuBao_transform`，然后将输出和目标数组交给 `memcmp`。

```asm
; IDA 中的 RVA
184F  lea  rdx, XueYuBao_target
1856  lea  rax, [rbp+transformed]
185A  mov  r8d, 0Ah
1860  mov  rcx, rax
1863  call memcmp_0
1868  test eax, eax
186A  setz al
186D  movzx eax, al
```

`memcmp` 返回 0 时，`setz al` 把相等的结果转成 1，`XueYuBao_check` 再把这个 1 返回给 `main`。

### 字节变换

key 在 RVA `0x5050`，内容是 `XueYuBao`，有效长度为 8 字节。初始的 `previous` 取 key 的最后一个字节 `0x6F`。每轮的运算与第四周的 Python 脚本一致。

```python
mixed = ((value ^ key[index % 8]) + previous + index) & 0xFF
previous = ((mixed << 3) | (mixed >> 5)) & 0xFF
output[index] = previous
```

汇编用 `xor`、`add` 计算 `mixed`，再通过 `AL` 写入单字节变量，保留低 8 位。后面的 `lea` 计算乘 8，`shr al, 5` 取高 3 位，再用 `or` 合并，通过低 8 位得到循环左移的结果。

## 反编译入门：从汇编到伪代码

反汇编保留每条机器指令，适合确认寄存器、内存宽度和跳转；反编译进一步把控制流和数据流恢复成类 C 伪代码，适合先看懂整体逻辑。伪代码不是原源码，函数名、变量名、类型和数组边界通常是工具推断出来的，仍要回到汇编、原始字节和调试结果核对。

本报告使用 IDA 9.5 的 Hex-Rays。在 `XueYuBao_check` 上按 `F5` 可以看到长度判断和比较，再进入 `XueYuBao_transform` 可以看到循环。下面是清理栈注释后的核心伪代码，变量名与正文统一。

```c
int XueYuBao_check(const char *input)
{
    unsigned __int8 transformed[10];

    if (strlen(input) != 10)
        return 0;

    XueYuBao_transform((const unsigned __int8 *)input, transformed, 10);
    return memcmp(transformed, XueYuBao_target, 10) == 0;
}

void XueYuBao_transform(const unsigned __int8 *input,
                        unsigned __int8 *output,
                        size_t length)
{
    uint8_t mixed;
    size_t index;
    uint8_t previous;

    previous = XueYuBao_key[7];
    for (index = 0; index < length; ++index)
    {
        mixed = previous
              + (XueYuBao_key[index % 8] ^ input[index])
              + index;
        previous = (8 * mixed) | (mixed >> 5);
        output[index] = previous;
    }
}
```

### 伪代码怎样对应汇编

| 伪代码位置 | 汇编依据 | 阅读结论 |
|---|---|---|
| `strlen(input) != 10` | `call strlen`、`cmp rax, 0Ah`、`jz` | 输入必须正好 10 字节，否则直接返回 0 |
| `transformed[10]` | `sub rsp, 30h`、`lea rdx, [rbp+transformed]` | 这是变换结果的局部缓冲区 |
| `previous = key[7]` | `mov [rbp+key_length], 8`、`lea rdx, [rax-1]`、`movzx` | 初始值取 key 的最后一个字节 `0x6F` |
| `key[index % 8]` | `div [rbp+key_length]`，余数在 `rdx` | 每轮按 8 字节 key 循环取值 |
| `8 * mixed` | `lea edx, ds:0[rax*8]` | 左移 3 位 |
| `mixed >> 5` | `shr al, 5` | 取出原来的高 3 位 |
| `(8 * mixed)` 与 `(mixed >> 5)` 按位或 | `or eax, edx` | 合并成循环左移 3 位的结果 |
| `output[index] = previous` | `mov [rdx], al` | 只写入低 8 位，即保留一个字节 |
| `memcmp(...) == 0` | `call memcmp_0`、`test eax, eax`、`setz al` | 相等时返回 1，失败时返回 0 |

这里最容易看漏的是字节宽度。伪代码中的 `uint8_t` 会让 `(8 * mixed) | (mixed >> 5)` 最终截断到低 8 位；如果误把它当成普通 `int`，就会丢掉溢出语义。汇编中的 `mov [rbp+previous], al` 和 `mov [rdx], al` 正好说明了这次截断。将该式与第四周 Python 的 `((mixed << 3) | (mixed >> 5)) & 0xFF` 对照，可以确认两者表示同一个 8 位循环左移。

### 反编译结果的可信度

伪代码适合用来建立假设，不适合单独作为最终结论。阅读时要依次确认：

1. 函数边界和参数是否合理，尤其是调用约定和指针类型。
2. 条件分支对应成功还是失败，返回值与 `main` 中的判断是否一致。
3. 循环下标、数组长度和写入宽度是否与节数据、汇编一致。
4. 是否被编译器内联、优化或替换成库函数。这份教学源码建议用 `-O0 -g -fno-builtin` 构建以保留较清晰的函数边界；换成优化版本后，函数形式可能变化。
5. 最后用正确输入、错误输入和断点读数验证，而不是只根据工具生成的变量名下结论。

对入门阶段，可以把反编译当作“先看地图”，把反汇编和调试当作“核对路标”。先回答输入在哪里、长度怎样限制、循环做什么、和什么比较、成功分支在哪里，再细看每个表达式。

## IDAPython 提取数据

在 IDA 中用 `Strings()` 找结果字符串，再用 `XrefsTo()` 找到引用。确认 `memcmp` 的第二个参数是 `XueYuBao_target` 后，按长度读取 10 字节。

```python
import ida_auto
import ida_bytes
import ida_funcs
import ida_idaapi
import ida_name
import idautils

ida_auto.auto_wait()
for item in idautils.Strings():
    if str(item).startswith("XueYuBao_result:"):
        for ref in idautils.XrefsTo(item.ea):
            print(f"{ref.frm:#x} {ida_funcs.get_func_name(ref.frm)} -> {item}")

target_ea = ida_name.get_name_ea(ida_idaapi.BADADDR, "XueYuBao_target")
if target_ea == ida_idaapi.BADADDR:
    raise RuntimeError("找不到目标数组")

target = ida_bytes.get_bytes(target_ea, 10)
if target is None or len(target) != 10:
    raise RuntimeError("目标数组读取失败")

print(f"{target_ea:#x}: {target.hex()}")
for ref in idautils.XrefsTo(target_ea):
    print(f"{ref.frm:#x} {ida_funcs.get_func_name(ref.frm)}")
```

运行输出如下。

```text
0x14000192d main -> XueYuBao_result: XueYuBao_input_error
0x140001986 main -> XueYuBao_result: XueYuBao_pass
0x14000199c main -> XueYuBao_result: XueYuBao_fail
0x140005060: 7be32f91ac8d9c1dd9c8
0x14000184f XueYuBao_check
```

最后一行对应上面的 `lea rdx, XueYuBao_target`。从 IDA 导出的数组、PE 文件偏移读出的字节和第四周脚本的目标一致。

## x64dbg 动态调试

### 跟踪第一次写入

在 x64dbg 里分别加载 `XueYuBaoNB` 和 `XueYuBaoNO`。在 `XueYuBao_check` 入口（RVA `0x1814`）看 `RCX` 指向的 10 个输入字节，两组只在最后一字节不同。

```text
XueYuBaoNB  58 75 65 59 75 42 61 6F 4E 42
XueYuBaoNO  58 75 65 59 75 42 61 6F 4E 4F
```

在 `XueYuBao_transform` 入口（RVA `0x1760`）取 `RDX` 中的输出缓冲区地址，对首字节下 1 字节硬件写断点。两组输入的第一个字节都是 `0x58`，与 key 的第一个字节异或后为 0。加上初始值 `0x6F` 和下标 0，得到 `mixed = 0x6F`，循环左移后为 `0x7B`。

实际写入指令在 RVA `0x17FB`，是 `mov [rdx], al`。本次调试中首字节从 `00` 变成 `7B`，断下时 `RIP` 已指向下一条指令 `0x17FD`。

### 比较两组输入

在 RVA `0x1863` 的 `memcmp` 调用前停住。Windows x64 调用约定下，`RCX` 指向变换输出，`RDX` 指向目标数组，`R8 = 0xA`。在内存窗口按 10 个原始字节查看。

| 项目 | `XueYuBaoNB` | `XueYuBaoNO` |
| --- | --- | --- |
| `RCX` 指向的输出 | `7be32f91ac8d9c1dd9c8` | `7be32f91ac8d9c1dd9e0` |
| `RDX` 指向的目标 | `7be32f91ac8d9c1dd9c8` | `7be32f91ac8d9c1dd9c8` |
| `memcmp` 返回值 | `0` | `1`（本次读数） |
| 校验函数返回值 | `1` | `0` |
| `main` 中 `test eax, eax` 后的 ZF | `0` | `1` |
| 执行 `jz` 后的位置 | `0x1986`，输出 `XueYuBao_pass` | `0x199C`，输出 `XueYuBao_fail` |

两组输入的前 9 个输出字节相同，最后一个字节分别为 `C8` 和 `E0`。用 GDB 17.2 重跑也得到相同的比较数据和跳转位置。

## 上周内容补

### C 实现与 Python 变换的一致性

第四周除了四组 Python 实验，还编译了 `XueYuBao_check.c`，用同一个字节变换核对 C 和 Python 的结果。

```c
const size_t key_length = sizeof XueYuBao_key - 1;
uint8_t previous = XueYuBao_key[key_length - 1];

for (size_t index = 0; index < length; ++index) {
    uint8_t mixed = (uint8_t)(
        (input[index] ^ XueYuBao_key[index % key_length])
        + previous + index
    );
    previous = (uint8_t)((mixed << 3) | (mixed >> 5));
    output[index] = previous;
}
```

| 项目 | Python | C | 一致性说明 |
|---|---|---|---|
| key 长度 | `len(key)` | `sizeof key - 1` | 不把字符串结尾的 NUL 算入 key |
| 初始状态 | `previous = key[-1]` | `key[key_length - 1]` | 都从 `0x6F` 开始 |
| 低位截断 | `& 0xFF` | 转为 `uint8_t` | 都只保留低 8 位 |
| 循环左移 | `(mixed << 3)` 与 `(mixed >> 5)` 按位或，再 `& 0xFF` | 同样按位或后写入 `uint8_t` | 8 位溢出语义相同 |
| 正确输出 | `7be32f91ac8d9c1dd9c8` | 同左 | C 与 Python 都能得到目标数组 |

`-O0 -g -fno-builtin` 便于后续在 IDA/x64dbg 中观察函数和库调用：

```powershell
gcc .\examples\XueYuBao_check.c -std=c11 -O0 -g -Wall -Wextra -fno-builtin -o .\examples\XueYuBao_check.exe
.\examples\XueYuBao_check.exe XueYuBaoNB
.\examples\XueYuBao_check.exe XueYuBaoNO
```

在 10 个位置分别遍历 256 种字节，共 2560 组正向输出的核对记录为 `XueYuBao_C_Python_transform_2560_checks: PASS`，见 [validation_results.txt](../wk4/validation_results.txt)。正确输入输出 `XueYuBao_result: XueYuBao_pass`，退出码为 0；错误输入输出 `XueYuBao_result: XueYuBao_fail`，退出码为 1。
