# 二、PE文件

## 一：含义

PE 全称 Portable Executable（可移植可执行文件格式），是 Windows 下常见的可执行文件格式。

## 二：常见类型：

### ·常见Windows系统 PE 文件包括：​\.exe \.dll \.sys

三种文件都是 PE，但用途不同 虽然格式同源，但它们的用途不一样：

文件                               全称/用途                                                   特点  

\.exe                     Executable，可执行程序                    双击就能运行，有入口点，是典型的应用程序 

\.dll                Dynamic Link Library，动态链接库     不能直接双击运行，供其他程序调用，导出函数给别人用  

\.sys                          System，驱动程序                     运行在内核态（Ring 0），由系统加载，用于驱动硬件

### ·Linux 下常见可执行文件格式是 ELF

## ·三：内部结构：

### PE 文件内部的组成部件分为

#### · DOS Header

DOS Header 是 PE 文件的开头。把一个 exe 用十六进制编辑器打开， 看到的最开头是DOS HEADER的起始标志：4D 5A（十六进制），换算成十进制为77 100，在ASCII码中找到对应的就是MZ。DOS Header 中有一个重要字段 e\_lfanew，它记录 PE 头的位置，它是 DOS Header 里的一个 4 字节字段，存放着 NT Header 相对于文件开头的偏移量 （单位是字节），便于系统怎么找到 NT Header 在哪。因为 Windows 常见小端序（"端序"指的是 多字节数据在内存里怎么排列。其中小端序（Little\-Endian） ： 低字节放前面，高字节放后面 。  大端序（Big\-Endian） ：高字节\(权重大/数值大"的那部分\)放前面，低字节\(权重小/数值小"的那部分\)放后面。），所以看十六进制时要注意字节顺序\(也就是说在十六进制编辑器中要把字节倒过来才能看见真正的偏移值\)。

#### · DOS Stub

DOS Stub 是 PE 文件里 DOS Header 后面,NT Heaader前面的一小段程序。正因为有它，NT Header 才 不紧挨着 DOS Header ，所以需要 e\_lfanew 来指路。占一小段空间， 具体长度不固定 （常见几十到一百多字节），它是一段 真正的 16 位 DOS 程序代码 ，最典型的功能就是打印一句提示：This program cannot be run in DOS mode\.

作用在于：兼容性考虑，源于 DOS 和 Windows 的过渡历史： 

1\. 早期 DOS 系统不认识 PE 格式。 

2\. 如果在纯 DOS 环境下双击一个 Windows 的 \.exe，系统不会直接崩溃，而是会先执行这个 DOS Stub。 

3\. DOS Stub 打印出"此程序无法在 DOS 模式下运行"，然后正常退出。

#### · NT Header

NT Header 是 PE 文件里最核心的头部结构，它告诉系统"这是个什么程序、从哪开始执行、怎么加载"。它是加载器（Loader）的第一站 ：Windows 加载 exe 时，先读 DOS Header 找到 NT Header，再从 NT Header 里拿到"入口点","基址"，才知道怎么把程序装进内存。

里面包含：​

•PE 签名。

从文件开头，先经过 DOS Header，再用 e\_lfanew 定位到它。它开头有个签名 50 45 00 00（即 PE\\0\\0，为PE签名，起标识作用，看到这四个字节，就确认真正进入 PE 的正文了。）

•文件头。

描述这个文件的基本信息：用的什么 CPU 架构（x86/x64）、有几个节、时间戳等。

•可选头。

名字叫"可选"，实际必须存在 。里面装着加载程序最需要的信息

可选头里最关键的三样东西 

• 程序入口点（AddressOfEntryPoint）

程序 第一条真正执行的指令 在哪个位置。逆向分析时，这是最先要跳过去看的地方。

• 镜像基址（ImageBase）

程序被加载到内存时，期望的起始地址 。比如 exe 常是 0x400000，dll 是 0x10000000。

• 节表相关信息（Section Alignment / File Alignment 等）

描述节怎么对齐、怎么映射到内存，是后续解析 Section Table 的依据。

##### 我的疑惑点：

程序入口点和镜像基址区别是什么？

镜像基址是PE文件被运行并被加载到内存中时，它期望自己整个文件被存放在内存的哪个起始地址。

程序入口点是PE文件已经躺进内存后，CPU应该从哪里开始执行第一行代码。

#### ·Section Table（节表）

节表就是一张清单，每一项描述一个"节"的信息。 每一项大小固定 40 字节 ，常见包含：

• 节的名称 ：如 \.text、\.data、\.rdata

• 虚拟大小 / 虚拟地址（RVA） ：这一节被加载到内存后占多大、放哪个地址

• 原始大小 / 原始偏移 ：这一节在 文件 里占多少字节、从文件第几个字节开始

• 节属性（Characteristics） ：这一节可读、可写、可执行吗

#### ·Sections（节）

Sections 就是节表里描述的那些实际数据块 ，是 PE 文件真正"装东西"的地方。常见的有：

表格       

节名                                               装什么                                      特点  

\.text                                              程序代码                                   可执行  

\.data                                   已初始化的全局/静态变量                      可读写  

\.rdata                                只读数据（字符串、常量）                        只读 

\.rsrc                                  资源（图标、菜单、对话框）                     只读  

\.reloc                                          重定位信息                                     只读  

\.bss （或 \.data 里）                     未初始化变量                            加载时才分配

# 三、对壳的了解和对于壳相关工具的使用

## 一\.对壳的理解

### 首先，作为初学者我需要知道什么是壳

壳就是给程序套在外面的一层代码，程序运行时会先执行这层代码，再由它把真正的原始程序还原并运行。拿到一个加了壳的 exe，双击运行时，CPU 最先执行的不是原始程序，而是壳 。壳跑完自己的任务（解压/解密），才把控制权交给里面的真身。

### 壳在 PE 结构上做了什么

壳会 改变程序的节表结构 ：

1\. 把原始节（\.text/\.data）压缩、加密 ，塞进新节里。

2\. 添加自己的节 ，通常命名成 UPX0、UPX1（UPX 壳的特征）。

3\. 改掉入口点 ：AddressOfEntryPoint 指向壳的代码，不再指向原始 main。

### 壳的常见类型

类型                                做什么                                              例子

压缩壳                            压缩体积                                            UPX

加密壳                   加密代码，运行时解密                        ASProtect、Themida  

保护壳                         防调试、防反编译                               VMProtect

### 壳的作用

1\.压缩体积 —— 文件更小，省空间、下载快。

2\. 增加静态分析难度 —— 挡住逆向者，用 IDA 直接看全是壳代码。

3\. 运行时再解压/解密 —— 原始代码不以明文存在磁盘上，保护源码逻辑。

## 二\.DIE——一款查壳工具

### DIE作用

1\.在进行逆向时弄清楚这是什么文件（PE/ELF,32/64,来自哪个编译器）

2\.弄清楚该文件是否加壳，如果加壳了就得先脱壳

### DIE判断原理

PE文件特征：

- 读文件开头，看是不是 MZ（DOS Header） 

- 用 e\_lfanew 找 PE\\0\\0 签名（NT Header） 

- 检查 Sectin Table 里节名是否正常（\.text/\.data） 

- 入口点是否指向正常区域

加壳会破坏这些特征 ——例如：节名变成 UPX0/UPX1、入口点异常——DIE 靠比对内置特征库，就能报出"这是 UPX 壳"。

### 010 editor是什么

010 Editor 是一款专业的十六进制编辑器（Hex Editor），是逆向/安全领域 最常用的二进制查看与编辑工具之一 。
