#### （七）多字节循环 key
```python
def xor_cycle(data, key):
    return bytes([b ^ key[i % len(key)] for i, b in enumerate(data)])

enc = bytes.fromhex("01020304")
key = b"key"
print(xor_cycle(enc, key).hex())
```

解释：
`xor_cycle` 函数：使每个数据字节与密钥对应字节异或，让密钥可以循环使用
（1）`enumerate(data)` :用来在遍历时同时拿到索引和值，省去手动维护计数器的麻烦
```python
for i, b in enumerate(data)
```
相当于
```python
for i in range(len(data))
    b = data[i]
```

（2）`b ^ key` ：使每个数据字节与密钥对应字节做异或
（3）`i % len(key)` ：让密钥索引始终在  \[0, len(key)-1]  范围内循环


注：同一段数据可能被 IDA、十六进制编辑器、Python 以不同形式展示，所以分析时要先判断它到底是按字节处理，还是按 16 位、32 位整数处理。
#### （二）大小端序
##### 1.大端序
高位字节在前
##### 2.小端序
低位字节在前
##### 3.在Python中大小端序的转换
```python
data = bytes.fromhex("78563412")
print(hex(int.from_bytes(data, "little")))  # 0x12345678
print(hex(int.from_bytes(data, "big")))     # 0x78563412
```

`int.from_bytes(bytes, byteorder, *, signed=False)` 函数可以实现大小端序的转换，其中
- `bytes` ：参数要转换的字节数据
- `byteorder`：字节序，只接受  "big"  或  "little"  这两个字符串值
- `*`：后面的参数只能关键字传参"的分隔符，防止  `signed`  被按错误的位置传进去。
- `signed`：是否按有符号数解释
#### （三）数据填充
当数据长度不满足算法分组长度时，程序可能会补齐数据。
常见填充：
| 填充方式 | 特征 |
| :---: | :---: |
| Zero Padding | 末尾补 `0x00` |
| 固定字符填充 | 末尾补固定字符，例如 `A`、`#` |
| 长度填充 | 补的内容和缺少的长度有关，例如 AES 里常见的 PKCS7 |

PKCS7：缺 n 个字节，就填充 n 个值都是 n 的字节
#### （四）数据分割
根据算法和大小端序，把数据切成合适单位。
常见分割方式：
- 按字节：12 34 56 78
- 按2字节：1234 5678

### 四、常见算法识别
#### （一）Base64
##### 1.常见特征：
- 字符串只包含大小写字母、数字、`+`、`/`、`=`。
- 结尾可能有 `=` 或 `==` 。
- CTF 中可能出现换表 Base64。
##### 2.加密过程：
1. 将输入数据按每 3 字节（24 位） 一组分组（不够 3 字节的可以在后面补 0）
2. 将 24 位拆成 4 个 6 位 的片段
3. 每个 6 位值（0-63）映射到 Base64 字符表`  A-Za-z0-9+/ `（或 `URL-safe` 变体）
4. 如果最后一组不足 3 字节，补 `=` 填充
#### （二）RC4
RC4 属于对称密码算法中的流密码（逐比特/字符加密）加密算法，核心是先打乱一个 256 长度的 S 盒，再生成密钥流和数据异或。
注：对称加密，即明文⊕密钥=明文，密文⊕密钥=明文
##### 1.常见特征：
- 出现长度为 256 的数组
- 有 `for i in range(256)` 类似逻辑
- 有大量 `% 256` 或 `& 0xff` 
- 有交换 `S[i]` 、 `S[j]` 的操作
- 分为 KSA 和 PRGA 两个阶段
##### 2.加密过程：
1. 对 S 表进行线性填充，一般为 256 字节
2. 用种子密钥填充另一个256字节的 K表
3. 用 K表 对 S表 进行初始置换
4. 为每个带加密的字节生成一个伪随机数，用来异或
注：表 S 一旦完成初始化，种子密钥就不再被使用。即 KSA 阶段用密钥，PRGA 阶段只靠 S 表的状态生成密钥流，不再使用原始密钥。
Python模板
```python
def rc4(data: bytes, key: bytes) -> bytes:
    s = list(range(256))
    j = 0

    for i in range(256):
        j = (j + s[i] + key[i % len(key)]) & 0xff
        s[i], s[j] = s[j], s[i]

    out = bytearray()
    i = 0
    j = 0

    for b in data:
        i = (i + 1) & 0xff
        j = (j + s[i]) & 0xff
        s[i], s[j] = s[j], s[i]
        k = s[(s[i] + s[j]) & 0xff]
        out.append(b ^ k)

    return bytes(out)
```

##### 3.解密过程：
初始化完全相同，生成完全相同的密钥流，密文字节再异或一次即恢复明文，因为 (P ^ K) ^ K = P
#### （三）TEA
TEA（*Tiny Encryption Algorithm*）是微型分组对称加密
##### 1.参数：
- 块大小：64 位（两个 32 位无符号整数 v\[0\] 和 v\[1\]）
- 密钥：128 位（4 个 32 位无符号整数 k\[0\] k\[1\] k\[2\] k\[3\]）
- 轮数：64 轮（推荐 32 次迭代，每迭代改两个半块，共 64 次半轮）
- 魔数 delta：`0x9E3779B9`（黄金比例 φ 的 2³¹ 倍）
##### 2.加密过程：
1. 将 64 位明文拆成两个 32 位无符号整数 v0 和 v1（小端序）
2. 将 128 位密钥拆成 4 个 32 位整数 k\[0\] k\[1\] k\[2\] k\[3\]
3. 定义常量 `delta = 0x9E3779B9`，累加器 `sum = 0`
4. 重复以下步骤，共 32 次：
  （1）`sum = sum + delta`
  （2）`v0 = v0 + (((v1 << 4) + k[0]) ^ (v1 + sum) ^ ((v1 >> 5) + k[1]))`
  （3）`v1 = v1 + (((v0 \<\< 4) + k\[2\]) ^ (v0 + sum) ^ ((v0 \>\> 5) + k\[3\]))`
5. 32 次迭代后，将 v0 和 v1 拼接为 64 位密文
##### 3.解密过程：
解密与加密完全对称，只是：
- sum 初始值不同（0 vs delta×32），方向相反（加 vs 减）
- 内部操作 `+=` 变 `-=`
- 解密先算 v1 再算 v0（加密时先进 v0 再进 v1 的结果需要按反向顺序回退）
##### 4.XTEA、XXTEA

| TEA  | XTEA |
| :---: | :---: |
| 左右运算不对称 | 左右完全对称 |
| 子密钥固定顺序 `k[0] k[1] / k[2] k[3] ` | 子密钥由 `sum` 动态选：`k[sum & 3] k [(sum>>11) & 3]` |
| `(v<<4)+k[n]` 和 `(v>>5)+k[n])` 分离 | 把移位和子密钥揉在一起：`(v<<4)^(v>>5)` 再 `+v` |
| 存在等效密钥攻击 | 修复了等效密钥问题 |
| 每轮更新 `sum` 在左半后 | `sum` 更新只在左半之前，右半之前不变 |

|  | TEA/XTEA | XXTEA |
| :---: | :---: | :---: |
| 调用方式 | 循环调用 5 次，每次传 `v[2]` | 一次调用，传 `v[10]` |
| 块间关系 | 无（除非外面加 CBC） | 所有字节天然相关，环形传播 |
| 轮数 | 固定 32 | `6 + 52/10 ≈ 11` 轮（但数据多所以每轮覆盖全数组，等效强度更高） |

#### （四）AES
AES属于对称加密中的分组加密算法（取代不安全的DES加密算法）
##### 识别方法：
###### 1.代码层识别
- Java/Android：查找  `Cipher.getInstance`("`AES/...`") ，常带模式参数如  AES/CBC/PKCS5Padding ，配合  SecretKeySpec  使用
- JavaScript：典型特征是  `CryptoJS.AES.encrypt(...)`  调用
- Native 层：搜索  `aes_set_key` 、 `aes_cbc_encrypt`  等 OpenSSL 风格函数名
- 常量表：AES 使用固定 S 盒（以  `0x63`, `0x7c`...  开头），逆向时搜索 S 盒表或轮常数即可定位
###### 2.数据层识别
- 分组大小固定：AES分组长度恒为 128位（16字节） 
- 密钥长度固定：只能是 16、24、32字节 之一，分别对应 AES-128、AES-192、AES-256
- 密文长度特征：密文长度是16字节的整数倍（CBC等模式经填充后）；若使用随机填充，相同明文每次加密结果不同
###### 3.算法结构识别
AES的核心轮函数包含四个固定步骤：字节替代（SubBytes）→ 行移位（ShiftRows）→ 列混淆（MixColumns）→ 轮密钥加（AddRoundKey），最后一轮不执行列混淆。
注：不要只看单一特征，组合特征才可靠。比如看到  `Cipher.getInstance`  且伴有密钥长度检查，基本可以确定是AES
#### （五）MD5
MD5（128 位哈希，不可逆，不是加密）将任意长度消息处理后输出 16 字节摘要
##### 识别方法：
###### 1.代码层识别
- Java/Android：搜索  `MessageDigest.getInstance`("MD5") ，这是标准命名。常见关键词还有  MD5 、 MD5Util  等
-  JavaScript：典型特征是  `md5() ` 函数或  `CryptoJS.MD5()`  调用。
- Python： `hashlib.md5()`  是标配写法
- 常量指纹：MD5使用4个固定的32位幻数 `0x67452301`、`0xEFCDAB89`、`0x98BADCFE`、`0x10325476`，逆向时搜索这些常量即可快速定位
- T表常量：64个T表常量（如  `0xD76AA478` 、 `0xEBC7B756` ）也是可靠指纹，即使代码被混淆也难以隐藏
###### 2.数据层识别
- 输出固定32位：MD5输出恒为 128 位（16字节），通常表示为 32 位十六进制字符串（小写）或 28 位 Base64 编码 
- 字符范围：十六进制表示仅含  0-9  和  a-f ，可通过字符集快速初步判断
- 不可逆：MD5 是单向哈希，没有解密算法，只能通过彩虹表或枚举撞库"还原"
###### 3.算法结构识别
MD5以 512 位分组 处理输入，每个分组划分为 16 个 32 位子分组，经过 四轮共 64 步 运算。四轮分别使用非线性函数 F、G、H、I，每轮16次操作，涉及模加、循环左移等位运算。处理完所有分组后，4 个 32 位寄存器拼接输出 128 位哈希值
#### （六）SM4
SM4 是国家密码局发布的对称分组密码，Feistel 结构 + SPN 非线性层
##### 识别方法：
###### 1.代码层识别
- HarmonyOS：搜索  `createCipher("SM4_128|...")` ，transformation 格式为"算法名|加密模式|填充方式"，如  `SM4_128|ECB|PKCS7` 
- 密钥生成： `createSymKeyGenerator("SM4_128")`  是典型调用
- 常量指纹：SM4的S盒以 `0xD6`, `0x90`, `0xE9`, `0xFE`... 开头，这是最可靠的识别特征。密钥扩展还使用固定的FK常量和32个 CK 常量
- 硬件实现：Verilog/VHDL 中常见  `S_Box.v` 、 `Key_Extending.v` 、 `Round_Function.v`  等模块命名
###### 2.数据层识别
- 分组长度固定：128位（16字节） 
- 密钥长度固定：128位（16字节），与AES-128相同但 SM4 密钥长度不可变
- 密文长度：16字节的整数倍，与 AES 在数据层面难以直接区分，需结合其他特征判断

###### 3.算法结构识别
SM4采用 Feistel 网络结构（与 DES 类似，而非 AES 的 SPN 结构），进行 32 轮非线性迭代 。每轮轮函数包含：异或轮密钥 → S 盒非线性替换（8×8）→ 线性变换 L（循环移位+异或）→ 最终异或 。加解密结构相同，仅轮密钥使用顺序相反（加密用 rk0~rk31，解密逆序）。线性变换L由循环移位和异或组成：` L(S) = S ⊕ (S<<<2) ⊕ (S<<<10) ⊕ (S<<<18) ⊕ (S<<<24)`

### 五、常用Python库
#### （一）Pycryptodome
用于 AES、DES、RC4 等常见密码算法。
```python
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

key = bytes.fromhex("00112233445566778899aabbccddeeff")
iv = bytes(16)
enc = bytes.fromhex("00112233445566778899aabbccddeeff")

cipher = AES.new(key, AES.MODE_CBC, iv)
plain = cipher.decrypt(enc)

try:
    plain = unpad(plain, 16)
except ValueError:
    pass

print(plain)
print(plain.hex())
```
#### （二）z3-solver
用于约束求解
```python
from z3 import Solver, BitVec

x = [BitVec(f"x{i}", 8) for i in range(4)]
s = Solver()

for ch in x:
    s.add(ch >= 0x20, ch <= 0x7e)

s.add(x[0] ^ 0x12 == 0x74)
s.add(x[1] + 1 == 0x62)
s.add(x[2] == ord('c'))
s.add(x[3] == ord('d'))

if s.check().r == 1:
    m = s.model()
    print(bytes([m[ch].as_long() for ch in x]))
```


### 六、动态调试
#### （一）软断点
机器码 = 操作码 + 操作数
0xCC：中断指令
#### （二）硬件断点
硬件断点是通过位于 CPU 上的一组特殊寄存器来实现的，称为调试寄存器。比如 x86 架构的 CPU 上有 8 个调试寄存器（DR0-DR7），分别用于设置和管理硬件断点。
#### （三）内存断点
内存断点本质上不是一个真正的断点。当调试器设置一个内存断点时，实际上是改变一个内存区域或一个内存页的权限。操作系统对内存页会设置访问权限，可执行、可读、可写、保护页，这些访问权限可以组合。
