### 3.2 编译过程与参数
| 参数 | 含义 | 逆向时的联系 |
| --- | --- | --- |
| `-o` | 指定输出文件 | 名称不决定真实文件格式 |
| `-E` | 停在预处理结果 | 查看头文件展开与宏替换 |
| `-S` | 生成汇编后停止 | 对照编译器汇编文本 |
| `-c` | 生成目标文件后停止 | 此时尚未最终链接 |
| `-g` | 生成调试信息 | 可能帮助恢复变量名和源码行 |
| `-s` | 链接时移除符号等信息 | 与“不使用 `-g`”不同 |
| `-O0` | 关闭大部分优化 | 较便于观察源码对应关系 |
| `-O2` | 开启一组优化 | 变量位置、指令与控制流可能变化 |
| `-Wall` | 启用一组常见警告 | 并非所有警告 |
| `-masm=intel` / `-masm=att` | 选择受支持 x86 目标的汇编语法 | 先确认操作数顺序 |
| `-m32` | 请求 32 位目标 | 需相应工具链和库 |
| `-static` | 请求静态链接 | 受目标和静态库可用性影响 |


`-g` 可以与优化级别组合，`-O2` 也不等于去除所有符号。原实验同时改变优化级别与调试信息，变量名变化包含 `-g` 的影响。

### 4.1 汇编
| 指令 | 核心作用 | 阅读时关注 |
| --- | --- | --- |
| `mov` | 复制数据 | 值、地址或内存内容？操作数多宽？ |
| `lea` | 计算有效地址 | 本身不读取该地址里的数据 |
| `cmp` | 设置减法比较相关标志 | 后续按有符号还是无符号解释？ |
| `test` | 按位与并设置标志，不保存结果 | 常见 `test eax,eax` 检查零返回值 |
| `jmp` | 无条件跳转 | 实际目标基本块在哪里？ |
| `je / jz` | `ZF=1` 时跳转 | 最近哪条指令设置了标志？ |
| `jne / jnz` | `ZF=0` 时跳转 | 目标最终是成功还是失败？ |
| `ja / jb` | 无符号大于 / 小于 | 与有符号判断区分 |
| `jg / jl` | 有符号大于 / 小于 | 数据是否可能为负数？ |
| `call / ret` | 调用 / 返回 | 参数和返回值如何流动？ |
| `push / pop` | 压栈 / 出栈 | 保存了什么，栈指针如何变化？ |
| `xor` | 异或 | 数据变换，还是同寄存器清零？ |
| `add / sub` | 加减 | 位宽、截断与溢出 |
| `shl / shr / sar` | 左移、逻辑右移、算术右移 | 是否丢位，右移是否保留符号？ |
| `rol / ror` | 循环移位 | 位宽与循环位数 |
| `nop` | 空操作 | 对齐、填充还是人为替换？ |


成绩程序的实存汇编可以简化为：

```plain
cmp eax, 1       ; scanf 是否成功赋值一个整数
jz  valid_input
; 输入失败分支
valid_input:
mov eax, [rbp+score]
cmp eax, 3Bh    ; 0x3B = 59
jle fail        ; 有符号小于等于 59
```

## 六、0xGame 的 RE 题目复盘
### 6.1 re-4410707 / shadow-code：代码解密后再分析
**核心问题：**磁盘上的真实校验代码被加密，直接静态分析会错过关键逻辑。

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/61846800/1792313213835-b1c3b69e-c698-4617-bf2c-8220932fe72d.png)

题解从 `password:`、`wrong password`、`expand 32-byte k` 等字符串出发，结合 `VirtualProtect` 和调用关系定位自解密流程。`expand 32-byte k` 提供流密码相关线索，具体算法还应结合轮函数判断。

程序先恢复第一层 stub，再由它恢复第二层校验函数。题解分别在解密后断下，通过实际加载基址加 RVA 设置断点，避开 ASLR 导致的地址变化。真实校验把 8 字节输入按大端拼成整数，再执行：

```latex
x ^= 0x819173B095485D69
x  = ROL64(x, 0x15)
x  = (x + 0xE1D88535C1C4D1DD) mod 2^64
x ^= 0xF216C53D78B72357
要求 x == 0x6E4EA9AABAEB2EB4
```

逆推按相反顺序进行：异或最后常量、模减法、循环右移、异或首个常量，再按大端恢复 8 字节。本轮从原题解提取求解代码执行，并将结果交给原始程序，输出：

```latex
password = 8qFcjsMm
password: 0xGame{525ca739-1677-49e6-8c45-6065c57ead1a}
```

### 6.2 re-Reflect：追到内嵌 DLL 的验证函数
<!-- 这是一张图片，ocr 内容为： -->
![](images/re_wk1/re_Reflect_01_Cutter总览.png)<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/61846800/1792313132553-7ec06ff9-c38c-4b3a-9822-ad765df273f1.png)

题解沿导出名和成功提示，找到外层 `.rdata` 中 RVA `0x50C0`、长 `0x1400` 的密文；对字节执行旋转和异或后恢复 DLL。

`VerifyNode` 要求输入长 `0x29`，即 41 字节；后 17 字节形成校验序列，前 24 字节分两段交错变换：

```latex
mixed[2*j]   = (input[j] + 0x0C) mod 256
mixed[2*j+1] = (input[12+j] - 0x0C) mod 256
target[i]    = mixed[i] XOR key[i mod 17]
```

先用目标值与循环 key 异或得到 `mixed`，再拆偶数、奇数位置，分别减、加 `0x0C`，拼回输入。本轮运行现有脚本并把结果交给原程序，得到：

```latex
0xGame{OvO_A_MaSt3r_of_RRR3f1ec7_1o@der!}
Input flag: Correct! The reflective module accepted your flag.
```

知识迁移：遇到装载器，要追踪数据恢复位置、恢复模块和最终调用函数。完整反射装载还涉及导入、重定位等机制；本题还原脚本侧重提取模块并分析验证函数。
