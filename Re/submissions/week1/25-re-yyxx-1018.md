# gcc
### 概念和使用
**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">gcc</font>** 是一套免费开源的编译器集合，核心作用是把C/C++ 等代码，翻译成电脑能直接运行的机器语言（`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">.exe</font>` 可执行文件）

1. -o 指定输出文件名  
核心作用：修改编译后生成的可执行文件 / 目标文件的名字，不指定时默认叫 a.out（Linux）或 a.exe（Windows）
2. -S 只生成汇编文件，不继续编译  
核心作用：将 .c 代码编译成 .s 汇编文件，不生成 .o 目标文件和可执行文件
3. -c 只生成目标文件，不链接  
核心作用：只把 .c 代码编译成 .o 目标文件，不进行链接步骤，不生成可执行文件
4. -E 只进行预处理，查看宏展开 / 头文件展开  
核心作用：只执行预处理步骤（处理 #include、#define、#ifdef 等宏指令），输出预处理后的代码文件。
5. -g 保留调试信息，方便 gdb 调试  
核心作用：在生成的可执行文件中加入调试符号信息，让调试器（如 gdb）能对应到源码的行号、变量名。
6. -s 去掉符号信息，精简可执行文件  
核心作用：从可执行文件中剥离调试符号和表信息，减小文件体积，但程序无法再被源码级调试，也不利于逆向分析
7. -O0 关闭所有优化  
核心作用：禁用所有编译器优化，代码和汇编一一对应，不做任何重排、简化
8. -O2 开启较高等级优化，提升执行效率  
核心作用：开启中等偏上的代码优化，编译器会自动做循环展开、指令重排、常量传播等优化，让程序运行更快、体积更小。
9. -Wall 开启所有常见编译警告  
核心作用：启用所有基础级别的编译警告
10. -m32 生成 32 位程序（需环境支持）  
核心作用：强制生成 32 位可执行文件，而非默认的 64 位程序。
11. -static 静态链接所有依赖库  
核心作用：静态链接，将程序依赖的所有系统库（如 libc）直接打包进可执行文件，生成的文件无需额外依赖就能运行。

##### 汇编语言
1.栈初始化

```plain
push rbp
 mov rbp ,rsp
 sub resp,40h
```

+ `<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">push rbp</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：保存旧的栈基址</font>
+ `<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">mov rbp, rsp</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：把当前栈顶设为新的栈基址，后面所有变量都用 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">rbp+偏移</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 来定位</font>

2.变量声明

var_xx是给栈上的变量起一个临时的名字，刚好是连续五个元素每个占四个字节，而最后的var_4则是对应循环变量i

3.赋值

mov  目标  来源，从而把值存到栈的数组里

4.跳转和循环判断

```plain
cmp     [rbp+var_4],  4
 jmp      short loc_401584
```

+ `<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">cmp [rbp+var_4], 4</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：把当前的 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">i</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 和 4 比较</font>

# 花指令
## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">1无意义指令</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">这类指令</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">运行时不改变任何寄存器、标志位和栈状态</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，但会让伪代码变得臃肿、混乱，增加阅读难度。</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">1. 寄存器自抵消操作</font>
```plain
; 示例1：加减抵消，eax完全不变
add eax, 5
sub eax, 5

; 示例2：异或清零再恢复
xor eax, eax
add eax, 0x1234
sub eax, 0x1234

; 示例3：两次交换，结果不变
xchg eax, ebx
xchg eax, ebx
```

+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">效果：程序功能无任何变化，但 IDA 伪代码里会出现一堆无意义的加减、异或操作，干扰阅读。</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">2. 栈操作抵消（push/pop 对）</font>
```plain
push eax
push ecx
pop ecx
pop eax  ; 栈指针完全恢复，eax、ecx也不变

; 或者栈指针加减抵消
sub esp, 8
add esp, 8
```

+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">效果：栈平衡无变化，但 IDA 的栈帧分析会被干扰，可能无法正确识别局部变量和参数。</font>

---

## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">二、垃圾代码</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">这类花指令的核心是</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">利用线性扫描反汇编器的弱点</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，插入跳转到自身下一条指令的跳转，中间夹着无效字节，让 IDA 把无效字节当成指令解析，导致整个代码块反汇编错位。</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">1.「短跳转 + 垃圾字节」</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">asm</font>

```plain
; 原指令：mov eax, ebx
mov eax, ebx

; 花指令部分
jmp short next_code  ; 跳转到第八行
db 0xE8              ; 无效/非法字节，会让IDA解析错误
db 0x0F, 0x0B        ; 
next_code:

; 后续正常指令
add eax, 1
ret
```

+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">运行效果：</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">jmp</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 会直接跳过后面的无效字节，程序逻辑完全正常。</font>
+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">IDA 效果：IDA是静态编译，不会自动跳到第八行，依然每行逐步分析，线性扫描会把 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">0xE8</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 当成 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">call</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 指令解析，后面的指令全部错位，反汇编直接乱掉。</font>

---

## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">三、恒真 / 恒假条件跳转花指令</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">构造</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">永远为真或永远为假</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">的条件跳转，中间插入垃圾字节，让 IDA 错误解析控制流，破坏函数分析。</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">1. 恒假跳转</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">asm</font>

```plain
cmp eax, eax    ; eax和自己比较，ZF=1（相等）
jnz short bad   ; 只有ZF=0才会跳，这里永远不跳
db 0xE8, 0x00   ; 垃圾字节，IDA会错误解析这些字节
bad:
mov eax, ebx    ; 正常指令，永远会被执行
```

+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">ZF是上一步执行结果的表示，如果上一步结果为0，则ZF为0，jnz则是根据ZF的值判断是否会跳转</font>
+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">运行效果：</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">jnz</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 永远不跳转，垃圾字节永远不会被执行，程序正常运行。</font>
+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">IDA 效果：反汇编器会误以为存在跳转分支，把垃圾字节解析成指令，导致后面的指令错位。</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">2. 恒真跳转</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">asm</font>

```plain
or al, al       ; 只要al≠0，ZF=0，jz不跳；但可以改成恒成立的条件
jz short good   ; 或者用 cmp eax, eax / jz short good （恒成立）
db 0x0F, 0x0B   ; 垃圾字节，永远不会被执行
good:
mov eax, ebx    ; 正常指令
```

+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">运行效果：程序一定会跳转到 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">good</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，垃圾字节永远不会被执行。</font>
+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">IDA 效果：IDA 会错误地把 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">jz</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 当成可能不跳转，尝试解析后面的垃圾字节，导致反汇编出错。</font>

---

## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">四、破坏栈平衡的花指令（补充）</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">这类指令</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">成对修改栈指针</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，运行时栈最终是平衡的，但会让 IDA 的栈帧分析（Stack Frame Analysis）出错，无法正确识别函数的栈布局，导致伪代码生成失败或参数 / 变量识别错误。</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">1. 栈指针来回加减</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">asm</font>

```plain
sub esp, 4   ; 栈指针减4
add esp, 4   ; 栈指针加4，恢复原状
; 栈指针前后不变，但IDA的栈分析会被干扰
mov eax, [ebp+8]  ; 原本的参数访问指令
```

+ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">效果：IDA 可能会误以为栈不平衡，无法正确识别 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">ebp+8</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 这样的参数偏移。</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">2. 多余的 push/pop   </font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">asm</font>

```plain
push eax
push ebx
pop eax    ; 错误的pop顺序，栈指针恢复了，但寄存器被破坏？不，也可以故意成对push/pop相同寄存器
pop ebx
; 或者更隐蔽的
pushfd
popfd      ; 标志位压栈再弹出，无影响，但会干扰栈分析
```

 

# 数据处理
## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">一、字节与 bit</font>
1. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">bit（比特）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：计算机最小数据单位，只有 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">0</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">/</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">1</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，代表 1 位二进制。</font>
2. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">字节（Byte）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">1 Byte = 8 bit</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，是最常用数据单位，取值范围 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">0~255</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">（无符号）、</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">-128~127</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">（有符号）。</font>

## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">二、ASCII、hex、bytes 的关系</font>
### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">1. 定义</font>
+ **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">ASCII</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：字符编码，将字符映射为 1 字节数字，例：</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">'a' = 97</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>
+ **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">hex（十六进制）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：字节的可读文本形式，1 字节 = 2 位十六进制，例：</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">97 = 0x61</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>
+ **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">bytes</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：Python 原生字节类型，存储原始二进制数据，格式 </font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">b'xxx'</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">2. 相互转换</font>
1. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">ASCII 字符 → bytes：</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">b'a'</font>`
2. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">bytes → hex：</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">b'a'.hex() → '61'</font>`
3. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">hex → bytes：</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">bytes.fromhex('61') → b'a'</font>`
4. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">bytes → ASCII：</font>`<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">b'a'.decode('ascii') → 'a'</font>`

## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">三、大小端序</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">多字节数据在内存中的存储顺序，针对</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">2 字节及以上整数</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：</font>

+ **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">大端序（Big‑Endian）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">高位字节存低地址</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>
+ **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">小端序（Little‑Endian）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">低位字节存低地址</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">（x86 CPU 默认）。</font>
