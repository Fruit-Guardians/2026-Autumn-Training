## 异或运算XOR

## 按位与AND

按二进制每一位进行比较，只有两个位置都是 1，结果才是 1。任何数和1都等于它本身

### 规则

#### 取低位

- \& 1 = 看最后一位，用来判断奇偶。

- \& 0xFF = 只留 8 格，多余的扔掉。

这是逆向里出现频率最高 的 AND。反编译代码里看到 \& 0xFF、\& 0xFFFF，就是在截断。

#### 模拟 C 语言无符号整数溢出

c语言中无符号整数占一字节，最大是八位二进制数11111111也就是255，此时要是再加1会本来该进位到第 9 格，但根本没有第9格，于是会溢出八位变成0\.

AND 就是手动做这件事 。当用Python或别的高级语言，它们默认不会溢出（Python 的整数可以无限大，所以得自己砍掉多余的位来模拟C语言 的那种行为：

C 里的行为：c = \(c \+ 1\) \& 0xFF

python手动砍掉代码：

x = \(0xFF \+ 1\) \& 0xFF    \# 0x100 被 0xFF 一剪变成0x00

print\(hex\(x\)\)            \# 0x00  

## 加减运算

前文所述，c语言无符号整型只有八位，更多就会溢出，在反汇编过程我们用的是c语言（无符号整型有溢出限制），而重写这个逻辑脚本的时候我们用的是python（无溢出限制），所以二者要统一：

如果 C 代码中使用 unsigned char，Python 里通常需要加 \& 0xff 模拟溢出。

## 位移

移位就是把这每位上的数整体往左或往右挪，空出来的位置补 0，挤出去的位数直接扔掉。

举例：

x = 0x91
print\(hex\(\(x \>\> 2\) \& 0xff\)\)
print\(hex\(\(x \<\< 3\) \& 0xff\)\)

- 整体右移

挪之前： 1 0 0 1 0 0 0 1

结果：0 0 1 0 0 1 0 0   = 0x24

右移不会产生超过 255 的数（只会变小），\& 0xFF 在这里主要是 保险 ，保证结果一定是一个字节。

- 整体左移

0x91 \<\< 3

挪之前： 1001 0001

往左挪3：1001 0001 000       二进制末尾补3个0

这时 \& 0xFF 就不是保险，而是必须的 ：

0x488 = 0100 1000 1000

\& 0xFF =        1000 1000    只留低8位 = 0x88，挤到第 9 位以上的部分被砍掉了。

## 取反和交换

### 取反：\~

就是把每一位翻转，0变1，1变0。

例如：

x = 0x12

print\(\~x\)          \# \-19 是负数

print\(hex\(\~x\)\)     \# \-0x13

这里特别说明在python当中是不限位数的，所以八位以上默认为0，取反就全部变成一，开头的数为一表示负数，所以Python 用了 补码 表示负数，特别地，在python里面变补码规律是：\~x等于\-x\-1

0x12=00000000 \.\.\.0001 0010，所以\~0x12=1111111\.\.\.\.1110 1101

前面所有的1看作是他的负号，负号和后面的数读出来十六进制就是\-0x13

print\(hex\(\(\~0x12\) \& 0xff\)\)

取\-0x13后八位就是1110 1101，即十六进制0xED

### 交换

#### 常规三变量交换：

temp = a;   // 苹果先放手里

a = b;      // 橘子搬进 A

b = temp;   // 苹果从手里搬进 B

为什么必须用第三个变量？ 因为a = b这一句会覆盖掉a原来的值 。没有temp存着，苹果就丢了。

#### python中的交换区别于此，直接把三变量交换打包成一行：

a, b = b, a

#### 不用临时变量的三次 XOR交换

a ^= b     

b ^= a      

a ^= b      

利用了异或性质：a ^ b ^ b = a——同一个数异或两次，就还原了。

# 三，常见加密算法

## RC4 

是一种流加密算法，密钥长度可变，它加解密使用相同的密钥）因此也属于对称加密算法

### 完整流程

① 初始化 S 盒     S = \[0,1,2,\.\.\.,255\]       ← 一副新牌

② 用 key 洗牌     S\[i\], S\[j\] = S\[j\], S\[i\]   ← 洗牌（打乱顺序）

③ 逐字节加密/解密

每处理一个字节：

洗一次牌：S\[i\], S\[j\] = S\[j\], S\[i\]

抽一个字节：K = S\[\(S\[i\]\+S\[j\]\) % 256\]

数据 ^ K（密钥流） → 密文

### 特征

看到代码里出现 S\[i\], S\[j\] = S\[j\], S\[i\] 和 % 256、\& 0xFF，就知道是 RC4

## TEA

### 首先加密程序中比较重要的几个点：

- uint32\_t —— 就是4 字节的无符号整数，也就是有32位，范围是0 \~ 42 亿

TEA 全程在 32 位里算，所以要 \& 0xFFFFFFFF，不是 \& 0xFF。

- delta = 0x9e3779b9 —— 一个固定密码

它是黄金分割数乘 2³² 再取整。

- v 和 k —— 数据 和 钥匙

void encrypt\(uint32\_t \* v , uint32\_t \* k\) \{

u32 v0 = v\[0\], v1 = v\[1\];

u32 k0 = k\[0\], k1 = k\[1\], k2 = k\[2\], k3 = k\[3\];

v = 要加密的数据， 4 个字节 × 2 个 = 8 字节 （64 位） 

k = 密钥， 4 个字节 × 4 个 = 16 字节 （128 位）

### 主要过程

#### 加密过程

u32 sum = 0;

for \(int i = 0; i \< 32; i\+\+\) \{      // 重复 32 轮

sum \+= delta;                    // 每轮累加一次 delta



v0 \+= \(\(v1 \<\< 4\) \+ k0\) ^ \(v1 \+ sum\) ^ \(\(v1 \>\> 5\) \+ k1\);

v1 \+= \(\(v0 \<\< 4\) \+ k2\) ^ \(v0 \+ sum\) ^ \(\(v0 \>\> 5\) \+ k3\);

\}

\(v1 \<\< 4\) \+ k0       v1 左移 4 位 ，加第一段钥匙  

\(v1 \+ sum\)             v1 加上 当前累加的 delta  

\(v1 \>\> 5\) \+ k1       v1 右移 5 位 ，加第二段钥匙

用 v1 算出一坨东西，加到 v0 上。

再用更新后的 v0 算出一坨东西，加到 v1 上。

v0 和 v1 在互相喂数据，就这两个操作，重复 32 次。

- 为啥移位 4 和 5？ 

\<\< 4 = 乘 16 

\>\> 5 = 除 32  

位移量不同，是为了让上下两半错开 ，这样搅出来的结果没有规律，越乱越好。

- sum 为什么每轮都加 delta？

为了让每一轮的运算都不一样。 如果 32 轮全用同一个公式，加到最后就是简单累加，太好破解了。sum 一轮轮变，每轮的加法和异或结果都不同。这就像每轮换一个密码锁的数字 。

- 需要注意

v0 \+= \.\.\. 里的 \+ 是 32 位加法，超出32位会溢出截断 。C 里 uint32\_t 自动截断，Python 里不会，所以要 \& 0xFFFFFFFF。这就是昨天说的C 有边界、Python 没边界。

#### 解密过程

把加法反过来做

u32 sum = delta \* 32;   // 先直接跳到最后一轮，然后从最后一轮往回减

for \(int i = 0; i \< 32; i\+\+\) \{

v1 \-= \(\(v0 \<\< 4\) \+ k2\) ^ \(v0 \+ sum\) ^ \(\(v0 \>\> 5\) \+ k3\);   // 减

v0 \-= \(\(v1 \<\< 4\) \+ k0\) ^ \(v1 \+ sum\) ^ \(\(v1 \>\> 5\) \+ k1\);   // 减

sum \-= delta;                                             // 往回退

\}

- 逆序回退

加密时是先改 v0、再用新 v0 改 v1，解密要 逆序 ，先还原 v1、再还原 v0。

#### 分块加密总函数

void encrypt\_multiple\_blocks\(unsigned char \* text , unsigned char \* key\) \{

uint32\_t \*v = \(uint32\_t \*\)text;    // 把字节数组 "看成" uint32\_t 数组

uint32\_t \*k = \(uint32\_t \*\)key;

- \(uint32\_t \*\)text是强制类型转换 ——把原本声明为 unsigned char \* （字节指针）的 text， 重新理解为32 位整数数组。

for \(int i = 0; i \< 8; i \+= 2\)   // 一组只能加密八个字节

\{

encrypt\(v \+ i, k\);

printf\("加密后的数据：%u %u\\n", v\[i\], v\[i\+1\]\);

\}

- i \+= 2：每次走 2 个 uint32\_t = 8 字节 ，正好一个 TEA 块。 

- v \+ i：指针偏移，v\+2 指向第 2、3 个 32 位（即第 8 字节起）。 每次传进去正好 2 个 32 位。  

- encrypt\(v \+ i, k\)：把数据指针和钥匙指针都给 encrypt。 

- %u：无符号十进制输出，v\[i\] v\[i\+1\] 是加密后的两个 32 位整数。

#### 解密总函数

void decrypt\_multiple\_blocks\(unsigned char \* text , unsigned char \* key\) \{

uint32\_t \*v = \(uint32\_t \*\)text;

uint32\_t \*k = \(uint32\_t\*\)key;

for \(int i = 0; i \< 8; i \+= 2\)

\{

decrypt\(v \+ i, k\);

printf\("解密后的数据：%u %u\\n", v\[i\], v\[i\+1\]\);

\}

逻辑和加密一模一样 ，只是把 encrypt 换成 decrypt。

### 特征

- 0x9e3779b9 或它对应的负数 0x61c88647，几乎就是 TEA。

- 出现 \<\< 4 和 \>\> 5 同时出现

- 出现 32 次循环 \+ 一堆 ^ 和 \+

- 看到字节指针强转成整数指针就往 TEA 上想。

## xTEA

XTEA 把"死用四把钥匙"改成了"按 sum 动态挑钥匙"，这就是它名字里 X 的意义（eXtended，增强版）

### 过程

#### //encrypt过程

for \(int i = 0; i \< rounds; i \+\+\) \{

v0 \+= \(\(\(v1 \<\< 4\) ^ \(v1 \>\> 5\)\) \+ v1\) ^ \(sum \+ k\[sum \& 3\]\);

sum \+= delta;

v1 \+= \(\(\(v0 \<\< 4\) ^ \(v0 \>\> 5\)\) \+ v0\) ^ \(sum \+ k\[\(sum \>\> 11\) \& 3\]\);

\}

右半边：\(sum \+ k\[sum \& 3\]\)

sum \& 3：取 sum 的 最低 2 位，结果只能是 0、1、2、3

k\[0\~3\]：正好命中 4 把钥匙之一

所以每轮挑的钥匙都不一样，而且由 sum 决定。之前学的 \& 取低位，在这里派上用场了—— \& 3 就是别超过3（两位二进制数） ，保证下标不越界。

改v1：
v1 \+= \(\(\(v0 \<\< 4\) ^ \(v0 \>\> 5\)\) \+ v0\) ^ \(sum \+ k\[\(sum \>\> 11\) \& 3\]\);

和改 v0 一模一样，只是： 

换成用 v0 来算 （注意：用的是第①句 已经更新过 的 v0）； 

取钥匙的下标换了 ：k\[\(sum \>\> 11\) \& 3\]： 右移 11 位再取最低 2 位

#### //decrypt过程

for \(int i = 0; i \< rounds; i \+\+\) \{

v1 \-= \(\(\(v0 \<\< 4\) ^ \(v0 \>\> 5\)\) \+ v0\) ^ \(sum \+ k\[\(sum \>\> 11\) \& 3\]\);

sum \-= delta;

v0 \-= \(\(\(v1 \<\< 4\) ^ \(v1 \>\> 5\)\) \+ v1\) ^ \(sum \+ k\[sum \& 3\]\);

\}

解密全程就是加密的镜像

### 区别于TEA：

1. 结构完全不同： 

TEA ：左移块和右移块各加一把不同的钥匙，三块平行异或； 

XTEA ：先把左移和右移异或起来 ，再 整体加 v1 。钥匙不在这块加。

- 为什么这样改？

因为 TEA 的三块对称结构有密钥调度弱点能被相关密钥攻击。XTEA 打乱这个对称性，安全性更好。

2. 左移/右移的组合方式变了 （先 ^ 再 \+ v，而不是各加一把钥匙）

### 特征

看到 k\[sum \& 3\] 或 k\[\(sum \>\> 11\) \& 3\] 就是 XTEA

2\. 看到 \(v \<\< 4 ^ v \>\> 5\) \+ v 这种先异或再整体加的写法 —— XTEA 结构 

3\. 0x9e3779b9 还在 —— 说明它是 TEA 家族，只是变体。

# 四\.Z3

## 什么是Z3

一个超级计算器，给它一堆条件 ，它自动帮你找出满足这些条件的数 。

## 它的用法

1. Solver\(\)      创建求解器（建一个"解题机"）

2. s\.add\(\.\.\.\)    添加约束条件（告诉它规则）

3. s\.check\(\)    检查是否有解（问它"能解吗？"）

4. s\.model\(\)    输出模型（把答案给你）

5. BitVec —— 玩位运算

x = BitVec\('x', 8\)     \# 8 位无符号整数（unsigned char）

BitVec\('x', 32\) 对应 uint32\_t（32 位）； 

它在内部会正确处理溢出 ——不用自己写 \& 0xFF 了。

- 举个例子

x = Int\('x'\)          \# 声明一个未知整数 x

s = Solver\(\)          \# 建解题机

s\.add\(x \+ 3 == 10\)    \# 告诉它：x \+ 3 等于 10

s\.add\(x \> 5\)          \# 再告诉它：x 大于 5

print\(s\.check\(\)\)      \# sat（表示有解）

print\(s\.model\(\)\)      \# \[x = 7\]  ← 答案

print\(s\.model\(\)\[x\]\)   \# 7

## 为什么逆向要用它

因为逆向本质就是：已知加密后的结果，反推原来的数。 而很多加密算法里， 中间夹了一堆位运算、数组下标、判断分支很复杂。

## 不适用条件

简单条件用它，复杂算法自己写解密函数。

大块数据 （几百字节以上）变量太多，z3 搜不完 

复杂加密 （TEA 32轮）位运算层数太深，需要几小时

需要精确时间 z3 没保证
