# Burp Suite 基础知识点总结

## 一、软件定位
Burp Suite 是一款用于 Web 应用安全测试的集成平台，核心作用是作为浏览器与目标服务器之间的中间人，拦截、查看、修改双向 HTTP/S 流量[citation:10][citation:12]。

## 二、核心模块

### 1. Proxy（代理）
- **作用**：拦截浏览器与目标之间的请求和响应，支持查看、修改后放行[citation:5][citation:10]。
- **Intercept（拦截）**：开启后请求会被暂停，可点击 Forward 放行或 Drop 丢弃[citation:5]。
- **HTTP History**：记录所有经过 Proxy 的流量，即使未开启拦截也会保存，便于回溯分析[citation:5][citation:9]。
- **Match and Replace**：自动替换请求/响应中的指定内容，适合批量修改 Cookie、Header 等[citation:5]。
- **HTTPS 抓包**：需在浏览器或设备中安装 Burp 的 CA 证书，否则无法解密 HTTPS 流量[citation:4][citation:7]。

### 2. Target（目标）
- **作用**：定义测试范围（Scope），告诉 Burp 哪些主机和 URL 是本次工作的目标[citation:3][citation:6]。
- **Site map**：以树形结构展示已发现的目标目录和文件，支持按 URL 视图或爬取路径视图切换[citation:3]。
- **Scope 设置**：将目标加入范围后，Proxy 历史、Repeater、Intruder 等工具可只关注范围内流量，减少干扰[citation:11]。

## 三、常用辅助模块
- **Repeater**：手动修改并重发单个请求，用于细致测试参数和观察响应差异[citation:4][citation:13]。
- **Intruder**：自动化攻击模块，可用于暴力破解、参数枚举等[citation:4][citation:12]。
- **Decoder**：编码/解码工具，处理 URL 编码、Base64 等[citation:12]。
- **Comparer**：对比两个请求或响应的差异[citation:4]。

## 四、基础使用流程
1. 启动 Burp，确认 Proxy 监听端口（默认 8080）。
2. 浏览器配置代理指向 Burp，HTTPS 需安装 CA 证书。
3. 开启 Intercept 抓包，或直接通过 HTTP History 查看流量。
4. 将感兴趣的请求发送到 Repeater / Intruder 做进一步测试。
5. 在 Target > Scope 中设定范围，过滤无关流量。

# SQL 盲注与布尔注入知识点总结

## 一、盲注的核心概念

盲注（Blind SQL Injection）是指在 SQL 注入过程中，**应用不回显数据库查询结果，也不返回详细的错误信息**时采用的技术。攻击者无法直接看到数据，只能通过构造条件语句，观察应用响应的**差异**（页面内容变化、响应时间长短等）来间接推断数据内容[citation:1][citation:4]。

与普通注入的区别：普通注入可以直接在页面看到查询结果或报错；盲注只能“问”数据库真/假问题，根据回答反推答案。

## 二、布尔盲注

### 原理
布尔盲注通过构造返回 **True 或 False** 的条件，观察页面返回内容是否发生变化，来判断注入的条件是否成立[citation:1][citation:5]。适用于页面有稳定“真/假”状态差异（如“登录成功”vs“无结果”）的场景。

### 基本判断流程
1. **确认注入点**：输入 `and 1=1` 与 `and 1=2`，观察页面是否有差异。
2. **判断闭合方式**：尝试 `'`、`"`、`)` 等，找到能让条件正常执行的闭合符[citation:2]。
3. **逐字符推断数据**：利用 `length()`、`substr()`、`ascii()` 等函数，配合比较运算（`>`、`=`、`<`），逐位猜解数据库名、表名、字段名和数据内容[citation:2][citation:15]。

### 常用函数
- `length(str)`：返回字符串长度
- `substr(str, pos, len)`：截取子串
- `ascii(char)`：返回字符的 ASCII 码值
- 比较运算：`=`、`>`、`<` 用于逐位缩小范围

### 典型 Payload 示例
```sql
-- 判断数据库名长度是否等于 8
id=1' and length(database())=8 --+

-- 判断数据库名第一个字母是否为 's'
id=1' and substr(database(),1,1)='s' --+

-- 用 ASCII 码比较，效率更高
id=1' and ascii(substr(database(),1,1))>100 --+

XSS漏洞基本知识点
 
1. 定义
 
XSS（跨站脚本攻击）是常见Web漏洞，攻击者向网页注入恶意脚本代码，被浏览器解析执行，从而实现攻击。
 
2. 核心原理
 
网站对用户输入数据未过滤、未转义，可控恶意代码直接输出渲染到页面，浏览器误将恶意代码当做正常代码执行。
 
3. 分类
 
（1）存储型XSS
 
恶意代码保存到服务器数据库，永久生效，所有访问用户都会触发，危害最高。
 
（2）反射型XSS
 
恶意代码不存入服务器，通过URL参数临时触发，需要用户主动点击恶意链接。
 
（3）DOM型XSS
 
攻击仅在前端完成，不经过服务器，由前端DOM操作不当导致代码执行。
 
4. 主要危害
 
窃取用户Cookie、劫持会话、网页篡改、钓鱼攻击、跳转恶意网站、泄露用户信息。
 
5. 防御措施
 
输入过滤特殊字符、输出HTML转义、Cookie设置HttpOnly、配置CSP策略、禁止前端危险函数。
 
6. 总结
 
了解xss漏洞的基本原理，能够掌握XSS漏洞的触发条件、攻击方式与安全防护方法。

1. 题目场景

- 用户可以提交留言

2. 漏洞分析
 
- 输入内容存入服务器数据库
- 永久展示在前端页面
- 所有用户访问页面都会加载恶意JS
典型存储型（持久型）XSS，危害大于反射型

公开标准解题逻辑：
 
- 留言板、个人简介、公告栏优先判定存储型XSS
- 入门环境常过滤script标签，优先使用 img/svg事件绕过

6. 个人心得总结
 
通过这道题，我彻底区分了反射型XSS与存储型XSS的核心区别：存储型会把恶意代码保存在服务器，被动攻击所有访客，危害范围更广、持续性更强。同时学会了基础标签绕过思路：被过滤script时，可以使用图片、svg的事件属性执行JS，是CTF XSS最常用的入门绕过手段。
