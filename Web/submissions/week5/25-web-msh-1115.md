## 结果与总结
本周血量一部分文件上传的内容，完成了一些习题
上传漏洞的本质是传上去一个能执行的脚本，被服务器解释执行，就能跑服务器命令。问题不在"上传"本身，在上传之后服务器怎么处理、解释这个文件。

能利用的三个条件：
文件落在 web 容器能解析的目录里。
用户能通过网址访问到它。
内容没被安全检查、压缩、格式化改坏。三条缺一不可。

检测发生在哪一层
客户端 JavaScript，一般只校验扩展名；判断方法是还没发包就弹窗。不过一般做题都会先禁用试试》
服务端：Content-Type、文件内容头（GIF89a）、目录路径、扩展名、后缀黑名单、后缀白名单。
最外层还可能有 WAF。

绕过手法
客户端绕过：禁用 js 或 NoScript，用开发者工具删掉 onsubmit 的校验，或先传允许的类型再用 Burp 改后缀。
黑名单后缀：找漏网后缀（php3、php4、php5、phtml 等）、大小写（linux、php5.3 的 pHp）、末尾加点或空格（windows 会去掉）、双写 pphphp（删一次中间又拼回来）、::$DATA（NTFS 数据流，检查看到的和落盘的后缀不一致）。
MIME 绕过：把请求里的 Content-Type 改成 image/gif、image/jpeg 这类。
.htaccess 重写：Apache 的目录配置文件，用 AddType 或 SetHandler 让图片后缀被当 php 执行；它本身不是 php 后缀，黑名单不拦；只在 Apache 上有效。
文件头绕过：图片有固定文件头，GIF 是 GIF89a；图片马就是文件头加一句话木马，后缀用服务器允许的图片后缀。
配合文件包含：内容检查只查 php、asp 这类脚本后缀时，先传一个 txt 木马，再用文件包含把它引进来执行。
