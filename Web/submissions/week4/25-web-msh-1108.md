## 结果与总结

本周继续学习PHP相关，主要学习离开函数安全和文件包含内容。

**函数安全**

- PHP 弱类型：`==` 松散比较会先做类型转换，`"0e123"`、`"1e9"` 这类字符串会被当成数字，导致"看起来不同、比较却相等"；校验应使用 `===`。
- 哈希弱比较：`md5()`/`sha1()` 结果以 `0e` 开头的字符串会被当成 0，两个不同的串因此相等；数组作为参数时函数返回 `NULL`，两个 `NULL` 同样相等。
- 字符串与数字互转：数字开头的字符串转数字、科学计数法可压缩长度，常用来同时满足"字数少"和"数值大"两个矛盾条件。
- 黑名单与替换：`str_replace`、`preg_replace` 等只替换一次或匹配不全时，可用双写、大小写、编码等方式绕过；`preg_match` 还常被换行、`/s` `/m` 修饰符绕过。
- 其他常见点：`strcmp()` 传数组返回 `NULL`、`%00` 截断（旧版本）、`is_numeric` 与 `intval` 处理不一致、反序列化中的魔术方法。
- 核心思路：找"校验时"和"使用时"对同一数据的理解差异，而不是正面硬碰。

**文件包含**

- 包含即执行：被包含文件里的 PHP 代码会被解析执行，所以想看源码必须让它以非 PHP 形式输出。
- 常用伪协议：`php://filter`（过滤器读源码/写文件）、`php://input`（读 POST 正文）、`data://`（内联数据，需 `allow_url_include=On`）、`file://`、`phar://`、`zip://`。
- `php://filter` 的过滤器：`convert.base64-encode` 把源码编码后输出再本地解码；`convert.base64-decode` 用于把编码内容还原后写入文件。
- 读源码之外，还可利用日志、session、`/proc/self/environ`、上传的临时文件等做包含。
- 路径控制：`../` 目录穿越、绝对路径、伪协议前缀决定读取方式。
- 写文件 getshell：用 `php://filter/write=convert.base64-decode/resource=目标文件` 写入 base64 后的 PHP 代码，再访问该文件执行。
- 防御：关闭 `allow_url_include`、限制 `open_basedir`、用白名单而非黑名单校验路径。
