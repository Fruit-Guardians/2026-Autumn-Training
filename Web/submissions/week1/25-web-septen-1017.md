二、 知识点详细总结
 
1. Web安全常用工具总结
• HackBar
	• 概念：是一个浏览器插件。
	• 特点：类似于地址栏，但是里面的数据不受服务器触发的重定向等变化的影响。
	• 作用：可以帮助我们测试SQL注入，XSS等漏洞。
• Webshell管理工具
	• 蚁剑：网站管理工具，面向于渗透测试安全人员以及网站管理员。
	• 冰蝎：通信过程中使用AES加密，隐蔽性较强。
	• 哥斯拉：替代工具，功能强大。
• Burp Suite
	• 概念：使用Java编写的一个用于测试网络应用程序安全性的图形化工具。
	• 主要功能：
		1. 拦截、查看或者修改网络请求和响应。
		2. 扫描Web应用程序的安全漏洞。
		3. 自动化攻击Web应用。
		4. 对数据编码和解码。
• Sqlmap
	• 概念：是一款Python编写的SQL自动化注入工具。
	• 作用：用于探测目标是否存在SQL注入；获取目标数据库中的数据。 
2. 弱口令与默认口令（认证安全）
• 弱口令
	• 概念：指容易被猜测或通过技术手段快速破解的密码（一定是弱的）。
	• 特征：
		• 长度过短：如少于6-8位。
		• 内容简单：纯数字（如 123456）、连续字母（如 abcdef）、相邻键盘组合（如 qwerty）。
		• 与个人信息相关：用户名、姓名拼音、生日、手机号（如 zhangsan1990）。
		• 常见单词或模式：password、admin123、iloveyou。
		• 重复或规律字符：aaa111、abc123。
• 默认口令
	• 概念：指设备、软件、系统在出厂设置或初始安装时预设的统一密码（不一定是弱的）。
	• 示例：
		• TP-Link 路由器：admin / admin
		• D-Link 路由器/摄像头：admin / (空密码) 或 admin
		• 华为企业级设备：admin 或 root / (空密码) 或 Admin@123 
3. 常见编码与古典密码
• Base64 编码（编码不是加密）
	• 概念：一种基于64个可打印字符来表示二进制数据的表示方法。注意：这只是“编码”而非“加密”，是可以直接逆向还原的。
	• 特征：由大小写字母、数字和 +、/、= 组成。如果在CTF中看到长串的乱码，且以 Zm... 等格式开头，第一反应就可以试试Base64解码。
	• 解码方法：
		1. 在线工具：浏览器搜索“Base64 在线解码”。
		2. 浏览器控制台（快捷装X）：按 F12 打开开发者工具 -> 点击 Console（控制台） -> 输入 atob("需要解码的字符串") 然后回车，即可直接看到明文。

• 凯撒密码（Caesar Cipher）
	• 概念：一种古典加密算法。据传由凯撒大帝发明，将字母表统一向后（或向前）移动固定位数来进行替换。
	• 特征：文本看起来保留了原有格式（如 flag{...} 的形状），但里面的字母全“歪”了。
	• 解法：利用穷举法（一般偏移量是1-25，可以通过脚本或在线工具全部列出来），或者根据已知的 flag 格式进行推算。例如：密文 iodj 向前偏移3位就是 flag。 
 
三、 实战题目 Writeup (WP)
 
题目1：EzLogin（弱口令爆破）
• 解题思路：
	1. 信息收集与提示：根据题目页面提示，发现登录用户名
	2. 源码审计：查看网页源代码，发现提示该题考察的是弱口令爆破。
	3. 工具利用：使用 Burp Suite 抓取登录请求包，发送到 Intruder（入侵者）模块。
	4. 爆破执行：加载常见的密码字典进行爆破，最终得到用户密码，登录成功获取 flag。 

题目2：编码不是加密（Base64解码）
• 题目信息：题目给出一串神秘字符 ZmxhZ3tiYXNlNjRfaXNfbm90X2VuY3J5cHR9，并提示“这只是编码，不是加密”。
• 解题思路：
	1. 识别编码：观察字符串，由大小写字母和数字组成，没有奇怪的符号，符合Base64的典型特征。
	2. 执行解码：
		• 方法一：直接找个在线Base64解码网站粘贴进去。
		• 方法二（推荐）：按 F12 打开浏览器开发者工具，切换到 Console（控制台），输入 atob("ZmxhZ3tiYXNlNjRfaXNfbm90X2VuY3J5cHR9") 并回车。
3.获取Flag：成功解出明文 flag{base64_is_not_encrypt}。 

题目3：凯撒的回信（凯撒密码解密）
• 题目信息：题目给出一串字符 iodj{fdhvdu_lv_hdvb}，提示这是凯撒大帝的信，字母全“歪”了。
• 解题思路：
	1. 识别密码：观察格式，外层的 {} 和内部的 _ 没有变，只有字母变了，这很明显是保留了格式的古典密码，结合提示确定是凯撒密码。
	2. 推算偏移量：已知CTF的flag格式通常为 flag{...}，对比密文开头 iodj 和明文 flag，可以发现字母 i 向前移动3位变成了 f，o 向前移动3位变成了 l（即整体偏移量为3）。
	3. 获取Flag：将 iodj{fdhvdu_lv_hdvb} 所有字母向前推3位，得到正确的 flag：flag{caesar_is_easy}。 

 
四、 碎碎念（今日复盘）
• 工具熟练度：Burp Suite 和 F12 开发者工具是Web手的左右手。学会了用 Console 控制台的 atob() 快速解Base64，效率直线提升。
• 区分概念：“编码”和“加密”在CTF中经常被混淆。Base64只是改变了数据的外观以便于传输，任何人都能解开；而加密（如AES）则是为了保护数据机密性，必须有密钥才能解。以后看到乱码先想编码，看到长相奇怪的格式再想密码学。
